## Spacing Scale

Declared values (multiples of 4 only). All values expressed as Tailwind utility equivalents.

| Token | Value | Tailwind Class | Usage |
|-------|-------|---------------|-------|
| xs | 4px | `p-1` / `gap-1` | Icon gaps, dot indicators, inline padding |
| sm | 8px | `p-2` / `gap-2` | Compact element spacing, help link margin |
| md | 16px | `p-4` / `gap-4` | Default field spacing, label-to-input gap |
| lg | 24px | `p-6` / `gap-6` | Card/panel padding, section spacing |
| xl | 32px | `p-8` / `gap-8` | Step-to-step vertical separation |
| 2xl | 48px | `py-12` | Wizard vertical centering offset |
| 3xl | 64px | `py-16` | Page-level outer padding |

**Exceptions:**
- Touch/click targets for icon buttons (eye toggle, gear icon): minimum 44px × 44px hit area (`w-11 h-11` with centered icon). **Source:** WCAG 2.5.5 minimum touch target.
- Progress step dots: 8px diameter (`w-2 h-2`) with 16px gap between dots.
- Inline result area (success/error below "Test Connection"): 8px top margin from button (`mt-2`).

**Source:** Existing codebase uses `p-6`, `mb-6`, `gap-2`, `space-y-1`, `max-w-[480px]` — this scale extends that pattern.

## Interaction Contract

### Wizard flow

```
Step 1 (Source — Customer Jira Server)
  → fill URL + PAT
  → click "Test Connection"
  → test runs (spinner, fields locked)
  → success: inline success message, "Next" button enabled
  → failure: inline error message, fields unlocked, "Test Connection" re-enabled
  → click "Next" (only available after test success)

Step 2 (Destination — Company Jira Cloud)
  → fill URL + Email + API Token
  → same test-gate pattern as Step 1
  → click "Next" after test success

Step 3 (Summary)
  → read-only summary card: both connections shown with green checkmarks, base URLs, connected usernames
  → "Done" button closes wizard, renders main app
```

### State machine — "Test Connection" button

| State | Button label | Button state | Fields | Spinner |
|-------|-------------|--------------|--------|---------|
| Idle (not yet tested) | "Test Connection" | enabled | editable | hidden |
| Testing | "Testing..." | disabled | locked (`disabled`, `opacity-50`) | visible, left of text |
| Success | "Test Connection" | enabled | editable | hidden |
| Failure | "Test Connection" | enabled | editable | hidden |

"Next" button:
- Hidden until first test succeeds.
- After success: visible and enabled.
- After editing any field post-success: "Next" hidden again (user must re-test).

### PAT / API token field (SecretInput)

- Renders as `<input type="password">` by default (masked).
- Eye icon button on right edge (44×44px hit area) toggles to `type="text"` and back.
- Eye icon uses two states: eye-open SVG (when masked), eye-off SVG (when revealed).
- `aria-label` on toggle button: "Show token" / "Hide token".

### URL validation (client-side, inline)

- Triggered on `blur` from URL field.
- Rule: must match `^https://` — if not, show inline error `"URL must start with https://"` in `text-red-600 text-sm` directly below the field.
- Trailing slash stripped automatically on blur (no user-visible feedback needed).
- Malformed URL never reaches backend; "Test Connection" button remains disabled while URL field has inline error.

### "Where do I find this?" link

- Renders as `<a>` with `target="_blank" rel="noopener noreferrer"`.
- Positioned on the same line as the field label, right-aligned, `text-sm text-slate-500 hover:text-blue-600 underline`.
- Customer Jira (PAT): links to `https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html`
- Company Jira Cloud (API token): links to `https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/`

### Step transition

- No animated transitions (Claude's discretion: keep it simple for a desktop tool — instant render on step change).
- Step progress dots update immediately on "Next": completed step dot fills with `green-600`, active step dot fills with `blue-600`, future step dots use `slate-300`.

### Settings page (post-setup)

- Gear icon in AppShell header (top-right, 44×44px hit area) navigates to Settings page.
- Settings page renders two `ConnectionCard` components, one per connection.
- `ConnectionCard` shows: colored status dot (green = tested OK, red = not tested / error, slate = unknown), connection label, base URL in `text-sm text-slate-500`, "Last tested: X ago" in `text-sm text-slate-400`, [Edit] button.
- [Edit] button opens wizard at the relevant step (prefilled with existing credentials, masked). User must manually re-test; save does not auto-test.

## Accessibility Contract

- All form inputs have associated `<label>` elements linked via `htmlFor` / `id`.
- Inline result area (`TestResult`) uses `role="status" aria-live="polite"` — matches existing `StatusBadge` pattern.
- Error messages use `role="alert" aria-live="assertive"` for immediate announcement.
- Eye toggle button: `aria-label="Show token"` / `"Hide token"`, `aria-pressed={revealed}`.
- "Test Connection" button: `aria-busy={testing}` while spinner is active.
- Step progress: `role="list"` on container, each dot is `role="listitem"` with `aria-label="Step {N}: {label} — {completed|current|upcoming}"`.
- Focus ring: `focus-visible:outline-2 focus-visible:outline-blue-600 focus-visible:outline-offset-2` on all interactive elements.
- Input disabled state during test: `disabled` attribute + `opacity-50 cursor-not-allowed` visual.

## Layout Contract

### Wizard layout

```
┌─────────────────────────────────────────────┐
│         Step progress dots (top)            │
│                                             │
│   Step title (Display / text-2xl semibold)  │
│   Step subtitle (Label / text-sm muted)     │
│                                             │
│   ┌─────────────────────────────────────┐   │
│   │  Form card (slate-100/800, p-6)     │   │
│   │  [label]       [Where do I find?]  │   │
│   │  [input field - full width]        │   │
│   │  [validation error if any]         │   │
│   │                                     │   │
│   │  [label]       [Where do I find?]  │   │
│   │  [secret input + eye icon]         │   │
│   │                                     │   │
│   │  [Test Connection btn - full width]│   │
│   │  [Inline result area]              │   │
│   └─────────────────────────────────────┘   │
│                                             │
│                          [Next btn →]       │
└─────────────────────────────────────────────┘
```

- Wizard card: `max-w-[480px]` centered — matches existing DevStatusPanel pattern.
- Full-width layout via `flex items-center justify-center min-h-screen` on outer container.
- Form card: `bg-slate-100 dark:bg-slate-800 rounded-lg p-6` — matches existing panel style.
- "Next" button: right-aligned below the card, appears only after test success.
- "Test Connection" button: full width within the form card, `bg-blue-600 hover:bg-blue-700 text-white font-semibold rounded-md py-2`.

- Max content width: `max-w-[640px] mx-auto px-6 py-8`.
