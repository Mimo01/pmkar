## Component Inventory

Components touched by this phase. Executors must extend these files, not create new ones.

### CopyPreviewModal.tsx — New sections in the Source column

Add after the existing "Labels" `SourceFieldRow`:

**Attachments count row** (when `sourceTicket.fields.attachment.length > 0`):
- Label: `"Attachments"`
- Value: `"{N} file(s) will be copied"` — e.g. `"3 file(s) will be copied"`
- Component: existing `<SourceFieldRow>` — no new component needed
- When zero attachments: render nothing (no empty row)

**Comments count row** (when `sourceTicket.fields.comment.comments.length > 0`):
- Label: `"Comments"`
- Value: `"{N} comment(s) will be copied"` — e.g. `"5 comment(s) will be copied"`
- Component: existing `<SourceFieldRow>`
- When zero comments: render nothing

**Sub-tasks list** (when `sourceTicket.fields.subtasks.length > 0`):
- Label: `"Sub-tasks"`
- Value: comma-separated `"{KEY}: {summary}"` strings — e.g. `"CUST-101: Fix login timeout, CUST-102: Add retry logic"`
- Component: existing `<SourceFieldRow>`
- When zero sub-tasks: render nothing

**Linked issues list** (when `sourceTicket.fields.issuelinks.length > 0`):
- Label: `"Linked Issues"`
- Value: comma-separated `"{linkType}: {KEY} — {summary}"` strings — e.g. `"Blocks: CUST-200 — API rate limiting"`
- Component: existing `<SourceFieldRow>`
- When zero linked issues: render nothing

Work log count is NOT shown in the preview (count not available without a separate fetch — deferred per RESEARCH.md Open Question 3).

### CopyResultModal.tsx — Extended stepLabel()

Add new step type handlers before the final `return step.step` fallback:

**Attachment step** (`step.step.startsWith('attach:')`):
- Success: `"{filename} — attached"` — e.g. `"screenshot.png — attached"`
- Failure: `"{filename} — {step.detail || 'attachment failed'}"` — e.g. `"database-dump.sql — 413 too large"`

**Comment step** (`step.step.startsWith('comment:')`):
- Success: `"Comment {n} copied"` — e.g. `"Comment 1 copied"`
- Failure: `"Comment {n} — {step.detail || 'failed'}"` — e.g. `"Comment 2 — conversion failed"`

**Work log step** (`step.step.startsWith('worklog:')`):
- Success: `"Work log entry {n} copied"` — e.g. `"Work log entry 1 copied"`
- Failure: `"Work log {n} — {step.detail || 'failed'}"` — e.g. `"Work log 1 — 400 bad request"`

Step ordering in the result list:
1. `create_issue` (existing)
2. `convert_description` (existing)
3. `upload_image:*` (existing — inline images)
4. `attach:{filename}` (new — one entry per attachment file)
5. `comment:{n}` (new — one entry per comment, 1-indexed)
6. `worklog:{n}` (new — one entry per work log entry, 1-indexed)
7. `add_remote_link` (existing)

### No new components

Do not introduce new files. All UI changes are extensions of existing files.

## Interaction States

### CopyPreviewModal during copy phase

When `phase === 'copying'`:
- Progress bar visible: `h-1 bg-brand animate-pulse` (established pattern)
- `progressStep` text updates below bar as each step starts: e.g. `"Copying attachment 1 of 3..."`, `"Copying comment 2 of 5..."`
- Both columns dimmed: `opacity-50 pointer-events-none` (established pattern)
- "Copy to Company Jira" button: `disabled opacity-50 cursor-not-allowed` (established pattern)

Progress step strings (shown in the `<p>` under the bar):
- `"Uploading attachment {filename}..."` — during attachment steps
- `"Copying comment {n} of {total}..."` — during comment steps
- `"Copying work log entry {n} of {total}..."` — during work log steps

### CopyResultModal partial-success state

When `!allPassed` and at least `create_issue` succeeded:
- Title: `"Copy Finished with Errors"` (established pattern — no change)
- Failed steps show red X icon (`text-red-400`) + step label with reason
- Passed steps show green check icon (`text-emerald-400`)
- "Open in Company Jira" button still appears if `create_issue` succeeded
- Per D-06: each attachment failure shows the failure reason in `step.detail` (e.g. `"413 too large"`)

### Empty states (read-only tabs — no change from Phase 3)

These are established patterns. Do not alter them:
- No attachments: `"No attachments"` in `text-xs text-brand-muted`, centered with `py-16`
- No comments: `"No comments"` in `text-xs text-brand-muted`, centered with `py-16`
- No work log entries: `"No work log entries"` in `text-xs text-brand-muted`, centered with `py-16`

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Copy to Company Jira" (established from Phase 4 — no change) |
| Preview attachment count | "{N} file(s) will be copied" |
| Preview comment count | "{N} comment(s) will be copied" |
| Preview sub-tasks label | "Sub-tasks" |
| Preview linked issues label | "Linked Issues" |
| Progress — attachment | "Uploading attachment {filename}..." |
| Progress — comment | "Copying comment {n} of {total}..." |
| Progress — work log | "Copying work log entry {n} of {total}..." |
| Result — attachment success | "{filename} — attached" |
| Result — attachment failure | "{filename} — {reason}" (e.g. "screenshot.png — 413 too large") |
| Result — comment success | "Comment {n} copied" |
| Result — comment failure | "Comment {n} — {reason}" |
| Result — work log success | "Work log entry {n} copied" |
| Result — work log failure | "Work log {n} — {reason}" |
| Result title (all pass) | "Copy Complete" (established — no change) |
| Result title (partial fail) | "Copy Finished with Errors" (established — no change) |
| Attachment 302 failure hint | "Failed to download attachment (server may require Jira Server 8.17+)" |
| Empty state — no attachments | "No attachments" |
| Empty state — no comments | "No comments" |
| Empty state — no work log | "No work log entries" |
| Attribution prefix format | "**{Author Name} — YYYY-MM-DD HH:MM**" (bold, on its own line in ADF) |
| Work log attribution format | "**{Author Name} — YYYY-MM-DD ({timeSpent})**" (bold, on its own line in ADF) |
| Sub-task entry format | "{KEY}: {summary}" (plain text in ADF bullet list) |
| Linked issue entry format | "{linkType}: {KEY} — {summary}" (plain text in ADF bullet list) |
| ADF section heading — sub-tasks | "Sub-tasks" (h3 ADF heading node) |
| ADF section heading — linked issues | "Linked Issues" (h3 ADF heading node) |

Destructive actions in this phase: none. Copy is irreversible but not destructive — the source ticket is never modified. No confirmation dialogs introduced beyond the existing preview/confirm flow.
