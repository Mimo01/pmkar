**Change 1: commands.rs — Add sub-task child issue creation loop**

Insert a new section AFTER the worklog loop ends (after line 1650, the closing `}` of the worklog `if let Ok(wl_response)` block) and BEFORE the "Step 9: Update triage state" comment (line 1652). The `subtasks` variable is already defined at line 1187 and is in scope.

The new code creates each sub-task as a child issue in the target Cloud Jira:

```rust
// Sub-task child issue creation (COPY-05)
// Note: subtasks variable already defined at line 1187 for description footer
for st in &subtasks {
    let st_summary = st["fields"]["summary"].as_str().unwrap_or("Sub-task");
    let st_source_key = st["key"].as_str().unwrap_or("?");

    let st_create_body = serde_json::json!({
        "fields": {
            "project": { "key": "MYPROJ" },
            "issuetype": { "name": "Sub-task" },
            "summary": st_summary,
            "parent": { "key": target_key }
        }
    });

    let st_create_resp = client
        .post(format!("{}/rest/api/3/issue", trimmed_target))
        .header("Authorization", &cloud_auth)
        .header("Content-Type", "application/json")
        .body(serde_json::to_string(&st_create_body).unwrap_or_default())
        .send()
        .await;

    match st_create_resp {
        Ok(r) if r.status().is_success() => {
            let resp_text = r.text().await.unwrap_or_default();
            let resp_json: serde_json::Value = serde_json::from_str(&resp_text)
                .unwrap_or(serde_json::json!({}));
            let child_key = resp_json["key"].as_str().unwrap_or("?");
            steps.push(CopyStepResult {
                step: format!("subtask:{}", st_source_key),
                success: true,
                detail: Some(format!("Created as {}", child_key)),
            });
        }
        Ok(r) => {
            let status = r.status().as_u16();
            steps.push(CopyStepResult {
                step: format!("subtask:{}", st_source_key),
                success: false,
                detail: Some(format!("Sub-task creation returned {}", status)),
            });
        }
        Err(_) => {
            steps.push(CopyStepResult {
                step: format!("subtask:{}", st_source_key),
                success: false,
                detail: Some("Network error creating sub-task".to_string()),
            });
        }
    }
}
```

Important implementation notes:
- The `subtasks` variable is already in scope from line 1187 (`let subtasks = source_body["fields"]["subtasks"].as_array().cloned().unwrap_or_default()`). Do NOT re-declare it. Just use `&subtasks` in the for loop.
- Use `client` (the audited client), NOT `plain_client` — this is a JSON POST, not multipart.
- The `target_key` variable holds the parent issue key (e.g. "PROJ-42"), already defined at line 1043.
- `cloud_auth` and `trimmed_target` are already in scope.
- `"project": { "key": "MYPROJ" }` matches the pattern from line 999 of the existing create_body for the parent issue.
- The mock server's `v3::create_issue` handler already accepts any fields and returns `{ "id": "...", "key": "PROJ-N" }` — no mock server changes needed.
- Step name format: `subtask:{source_key}` (e.g. `subtask:CUST-101`) to identify which source sub-task was processed.
- On success, detail includes the created child key (e.g. "Created as PROJ-43").
