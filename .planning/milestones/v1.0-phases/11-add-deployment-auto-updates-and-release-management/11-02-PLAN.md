1. **`.github/workflows/release.yml`** — Create the tag-triggered release workflow. Structure:

```yaml
name: Release

on:
  push:
    tags:
      - 'v*'

jobs:
  create-release:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    outputs:
      release_id: ${{ steps.create_release.outputs.id }}
      changelog: ${{ steps.changelog.outputs.content }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Generate changelog
        id: changelog
        uses: orhun/git-cliff-action@v4
        with:
          config: cliff.toml
          args: --latest --strip header

      - name: Create release on public repo
        id: create_release
        uses: softprops/action-gh-release@v2
        with:
          repository: AurelianSpowormo/pmkar-releases
          tag_name: ${{ github.ref_name }}
          name: 'pmkar ${{ github.ref_name }}'
          body: ${{ steps.changelog.outputs.content || 'See release assets for download.' }}
          draft: false
          prerelease: false
          token: ${{ secrets.RELEASES_REPO_PAT }}

  build-tauri:
    needs: create-release
    permissions:
      contents: write
    strategy:
      fail-fast: false
      matrix:
        include:
          - platform: macos-latest
            args: '--target universal-apple-darwin'
            rust_targets: 'aarch64-apple-darwin,x86_64-apple-darwin'
          - platform: ubuntu-22.04
            args: ''
            rust_targets: ''
          - platform: windows-latest
            args: ''
            rust_targets: ''

    runs-on: ${{ matrix.platform }}
    steps:
      - uses: actions/checkout@v4

      - name: Install Linux system dependencies
        if: matrix.platform == 'ubuntu-22.04'
        run: |
          sudo apt-get update
          sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf

      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm

      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.rust_targets }}

      - uses: swatinem/rust-cache@v2
        with:
          workspaces: '. -> target'

      - run: npm ci

      - uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.RELEASES_REPO_PAT }}
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
        with:
          owner: AurelianSpowormo
          repo: pmkar-releases
          tagName: ${{ github.ref_name }}
          releaseName: 'pmkar ${{ github.ref_name }}'
          releaseBody: ${{ needs.create-release.outputs.changelog || '' }}
          releaseDraft: false
          prerelease: false
          args: ${{ matrix.args }}
```

Key design decisions:
- Per D-01: `owner: AurelianSpowormo` / `repo: pmkar-releases` for public releases repo
- Per D-02: macOS universal (`--target universal-apple-darwin`), Windows `.msi`, Linux `.deb` + `.AppImage`
- Per D-07: Triggered by `v*` tag push
- Per D-08: `tauri-apps/tauri-action@v0` automatically generates `latest.json` manifest
- Per D-09/D-10: No Apple notarization or Windows signing secrets — add later via secrets
- The `create-release` job runs first to generate changelog once, then build matrix jobs upload artifacts
- `softprops/action-gh-release@v2` creates the release on the public repo; `tauri-action` then uploads artifacts to the same release
- Using `--legacy-peer-deps` is NOT needed in CI since npm ci uses lockfile

2. **`cliff.toml`** — Create git-cliff configuration at repo root:

```toml
[changelog]
header = ""
body = """
{% for group, commits in commits | group_by(attribute="group") %}
### {{ group | upper_first }}
{% for commit in commits %}
- {{ commit.message | split(pat="\n") | first | trim }}\
{% endfor %}
{% endfor %}
"""
trim = true

[git]
conventional_commits = true
filter_unconventional = true
split_commits = false
commit_parsers = [
  { message = "^feat", group = "Features" },
  { message = "^fix", group = "Bug Fixes" },
  { message = "^refactor", group = "Refactoring" },
  { message = "^perf", group = "Performance" },
  { message = "^test", group = "Testing" },
  { message = "^docs", group = "Documentation" },
  { message = "^chore", group = "Miscellaneous" },
  { message = "^ci", group = "CI/CD" },
]
filter_commits = false
tag_pattern = "v[0-9]*"
sort_commits = "newest"
```

This parses the existing conventional commit format (feat:, fix:, docs:, etc.) used throughout the project.

  <action>
Create `scripts/bump-version.mjs` — a Node.js ESM script that synchronizes the version across all three files. Usage: `node scripts/bump-version.mjs 1.0.0`

The script must:
1. Accept a single argument: the new semver version string (e.g., `1.0.0`, `1.2.3`)
2. Validate the argument matches `/^\d+\.\d+\.\d+$/` — exit with error if not
3. Read and update these three files:
   - `package.json`: update `"version": "X.Y.Z"` using JSON parse/stringify (preserve 2-space indent)
   - `src-tauri/tauri.conf.json`: update `"version": "X.Y.Z"` using JSON parse/stringify (preserve 2-space indent)
   - `src-tauri/Cargo.toml`: update `version = "X.Y.Z"` using regex replace on the line matching `^version = "` in the `[package]` section
4. Print which files were updated and the old -> new version
5. Exit 0 on success, 1 on error

Use `node:fs` and `node:path` with `import.meta.url` for paths. Resolve file paths relative to the script location (one level up from scripts/).

Example output:
```
Bumping version to 1.0.0
  package.json: 0.1.0 -> 1.0.0
  src-tauri/tauri.conf.json: 0.1.0 -> 1.0.0
  src-tauri/Cargo.toml: 0.1.0 -> 1.0.0
Done. Run: git add -A && git commit -m "chore: bump version to 1.0.0" && git tag v1.0.0 && git push origin v1.0.0
```

This addresses the version mismatch pitfall (Pitfall 3 in RESEARCH.md) — all three files must be at the same version before tagging.
