## Bugs Found During Validation Testing

Functional bugs discovered while validating the milestone. Status at audit time:

### B-01 — UNIQUE INDEX blocks mandatory field gap resolution (COMMITTED FIX — working tree)

**Affected:** OVRD-04, OVRD-05, MAP-03, MAP-04
**Root cause:** `ADD_UNIQUE_TARGET` migration added an unconditional `UNIQUE INDEX` on `target_field_id` including the empty-string dismissed-suggestion sentinel (`''`). Any attempt to add a second mapping row (which starts as `targetFieldId=''`) failed with a UNIQUE constraint. The mandatory field remained in `gapFields` indefinitely — warning persisted even after the user configured a mapping.
**Fix:** Changed `DEDUP_TARGETS` to only deduplicate non-empty rows; added `DROP_OLD_TARGET_INDEX` migration; changed `ADD_UNIQUE_TARGET` to partial index `WHERE target_field_id != ''`.
**Status:** Fix in working tree (`src-tauri/src/field_mapping_db.rs`), not yet committed. All 182 lib tests pass with fix.

### B-02 — `description` field missing from Bug/Task/Story mock createmeta fixtures (COMMITTED FIX — working tree)

**Affected:** DISC-03, DISC-04, TRAN-02, indirectly MAP-02 (seed defaults include description→wiki_to_adf)
**Root cause:** `build_fixtures()` in `fixtures.rs` omitted `description` from Bug (was 7 fields), Task, and Story issue-type createmeta field lists. The `wiki_to_adf` default seed mapping row could never be exercised against mock data because the target createmeta didn't expose the field.
**Fix:** Added `description` field to Bug (now 8 fields, 2-page pagination boundary), Task, and Story createmeta fixture lists. Updated `fetch_all_createmeta_drains_two_pages` test (total=8) and `createmeta_pagination.rs` (page2=3, total=8).
**Status:** Fix in working tree (`src-tauri/src/fixtures.rs`, `tests/field_discovery_integration.rs`, `tests/createmeta_pagination.rs`), not yet committed.

### F-01 — copyStore.test.ts missing `targetIssueTypeId` before `confirmCopy` (RESOLVED)

**Affected:** OVRD-03, CUTV-01
**Fix:** Added `targetIssueTypeId: 'it-1'` to `setState(...)` call in test.
**Status:** Committed (822d787).

### F-02 — CopyPreviewModal.test.tsx missing Phase 22 store fields (PARTIAL)

**Affected:** PERS-01..04, OVRD-01..06
**Fix:** Some Phase 22 fields added to `buildStoreState()`.
**Status:** Partially committed (3c32d8e). 17 stale tests remain — they assert legacy UI (status dropdown, priority dropdown, label checkboxes) that was fully replaced in Phase 22. `CopyPreviewModal.tsx` is a production orphan (imported only by its test file); production uses `CopyPreviewPage`. Full fix requires either wiring `CopyPreviewModal` into a dialog shell or deleting it and rewriting the tests against `CopyPreviewPage`.

### F-03 — registry.test.ts CTRL-07 priority assertion stale after PriorityRenderer addition (RESOLVED)

**Affected:** CTRL-07
**Fix:** Updated test to assert `PriorityRenderer` for `type: 'priority'`.
**Status:** Committed (b7cd876).

### B-03 — Copy-modal overrides not prefilling (RESOLVED)

**Root cause:** `overrideValues` in copyStore never seeded from field mapping rows on modal open. `startPreview` does not read `get_field_mapping`.
**Status:** Resolved — documented in `.planning/debug/resolved/`.

### B-04 — User and wiki_to_adf transformer kinds not prefilling (RESOLVED)

**Root cause:** `PREFILLABLE_KINDS` excluded `'user'` and `'wiki_to_adf'`. Source user objects are directly compatible with `UserPickerRenderer.isJiraUser()` validation; wiki string values are compatible with `TextAreaRenderer`.
**Fix:** Expanded `PREFILLABLE_KINDS` to include `'user'` and `'wiki_to_adf'` with a string-type guard for ADF objects.
**Status:** Committed (78adcc4).
