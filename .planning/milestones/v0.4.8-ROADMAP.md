# Milestone v0.4.8: Mapping Refinements & Static Values

**Status:** ✅ SHIPPED 2026-05-20
**Phases:** 24-27
**Total Plans:** 9

## Overview

Post-v0.4.0 hardening of the configurable field mapping engine, released incrementally as v0.4.1 → v0.4.8. Copy-time audit rows now show what `apply_mapping` actually resolved. Description (wiki→ADF) and user fields are resolved when the copy preview opens, so users can review them before copying. Ticket fetching runs one batch per watched user with a progress counter. A new `static` transformer kind lets target-only Jira Cloud fields receive a configured constant on every copy. About 70 quick tasks ran alongside the phases (UI polish, mock fidelity, transformer fixes, releases).

## Phases

### Phase 24: Audit Log Copy-Time Resolution

**Goal**: Add copy-time per-field audit entries to `copy_ticket_v2` so the Field Transformations log reflects actual `apply_mapping` resolution outcomes for `wiki_to_adf` and `user` fields — not just the preview-time pre-fill snapshot.
**Depends on**: Phase 23
**Plans**: 2 plans

Plans:

- [x] 24-01: Backend — `copy_id` on `CopyTicketV2Args`, copy-time audit loop (`write_copy_time_audit`), thread `previewCopyId` through copyStore
- [x] 24-02: Frontend — `copied` outcome badge (blue), EN+SK i18n keys, fieldGrouping tests

**Details:**
The `PREFILLABLE_KINDS` gate logged async fields as `skipped / target: null` at preview time, and the copy-time loop had been removed as "redundant." As a result, users saw nothing resolved. The audit loop now runs after the override merge, so rows reflect the final values sent to Jira.

### Phase 26: Batch Ticket Fetching per Watched User

## Milestone Summary

**Key Decisions:**

- Copy-time audit extracted as free fn `write_copy_time_audit` for testability; runs after override merge
- `copy_id: Option<String>` with server-side UUID fallback
- Preview resolution uses a plain `reqwest::Client`, so preview lookups do not pollute the HTTP audit log
- Description shown read-only in the preview target panel; ADF editor still deferred
- Fetch progress kept in local component state (not Zustand); per-user try/catch isolates failures; first-seen-wins dedup
- Static option values stored as `{id,value}` so the copy modal can show labels without a lookup
