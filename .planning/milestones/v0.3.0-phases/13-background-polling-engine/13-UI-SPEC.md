## Interaction Contracts

### Polling Section in Settings (POLL-01)

**Location:** `SettingsPage.tsx` — new `'polling'` case in the `ActiveSection` union type, rendered as a `SectionCard`.

**Sidebar placement:** New "Polling" nav group between "Fetching" and "Appearance" groups, separated by `<Separator />`. Nav label: `settings.group.polling` (i18n key).

**Frequency selector UI pattern:** Inline button group identical to `ThemeSection` (flex row, each option is a `<button>` with `flex-1`). Five options: `5m`, `15m`, `30m`, `1h`, `Off`.

Selected state: `border-brand/30 bg-brand/8 text-brand-text font-semibold ring-1 ring-brand/10`
Unselected state: `border-brand-border text-brand-muted hover:text-brand-text-secondary hover:bg-brand-surface-hover`

**Immediate effect:** Selection takes effect on click, no Save button (matches D-03 from CONTEXT.md, same as language/theme toggles).

**Disabled state:** When `Off` is selected, add `text-brand-muted` to section description. No disabled styling on other controls.

### Fetch Button Enhancement (POLL-03, D-10)

**Location:** FetchBar row in `TicketListPage.tsx` (lines 146–157).

**Behaviour change:** The existing Fetch button runs ticket fetch AND snapshot change detection in one action. No visual label change required — button label stays as `t('tickets.fetchButton')`.

**Active poll state:** `Loader2` with `animate-spin` already present for `isLoading`. Extend to cover both fetch-in-progress and poll-in-progress states using a shared `isLoading` boolean.

**Keyboard shortcut:** F5 triggers manual poll. No visual indicator needed in this phase — F5 is handled via `keydown` listener, not a visible badge.

### "Last Checked" Timestamp (D-13)

**Location:** FetchBar row, inline after the Fetch button.

**Existing element:** The `lastFetchedAt` span at `TicketListPage.tsx` line 158 already shows relative time. Rename/extend to reflect poll time: `t('tickets.lastChecked', { time: ... })` (new i18n key replacing or augmenting `tickets.lastFetched`).

**Update cadence:** Update on `poll-complete` Tauri event reception, not on a frontend timer interval.

**Format:** "Last checked: 2 min ago" — uses existing `formatRelativeTime()` utility.

### Poll-Complete Event Handling (D-15, D-16)

**Frontend event listener:** `ticketStore.ts` listens for `poll-complete` Tauri event. On receipt, silently re-invoke ticket list refresh (no toast, no banner). Ticket list auto-updates without user action.

**No layout shift:** Ticket list updates in-place. No "show N new items" prompt.

## Accessibility Contract

- Fetch button: `disabled` attribute set when `isLoading === true` (existing pattern preserved)
- Frequency buttons: each is a `<button type="button">` with visible text label — no icon-only controls
- Selected frequency: `aria-pressed="true"` on the active button (add to match ThemeSection/LanguageSection pattern which currently lacks it — add during implementation)
- "Last checked" span: `aria-live="polite"` — matches existing `lastFetchedAt` span attribute
- Settings sidebar nav: existing `aria-label="Settings navigation"` on `<nav>` covers new polling entry automatically
- F5 shortcut: document in `title` or `Tooltip` on Fetch button as "Refresh (F5)"
