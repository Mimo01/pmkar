| Token | Value | Usage |
|-------|-------|-------|

| sm | 8px | Compact element spacing, gap between toggle items (`gap-2`) |

| lg | 24px | Section content padding top/bottom (`py-6`) |
| xl | 32px | Major layout gaps |

- SectionCard inner padding: 20px (`p-5`) — matches existing settings sections exactly

## Interaction Contracts

### Notification event toggles

- Render as shadcn `Switch` component, right-aligned in each row
- Default state: all ON when notifications first enabled (D-08 from CONTEXT.md)
- Behavior: immediate-apply (no save button) — invoke Tauri command on toggle change
- Disabled state: entire section disabled with `opacity-50 pointer-events-none` when notifications permission denied
- Transition: standard switch animation from shadcn (no custom animation needed)

### Quiet hours time inputs

- Native `<input type="time">` — no third-party time picker (avoids registry dependency)
- Immediate-apply on blur (not on every keystroke) — invoke Tauri command on `onBlur`
- Default: empty / no quiet hours (D-12: quiet hours off by default)
- Validation: if start equals end, show inline caption error (12px `text-red-400`)

### Weekday toggles

- Button group using existing pill pattern from PollingSection
- `aria-pressed` on each button
- Immediate-apply on click
- At least one day must remain selected; if user attempts to deselect all, last remaining day stays selected and shows no visual change (silent guard)

### Permission denied banner

- Shown when Tauri notification permission API returns denied
- NOT dismissible (no X button) — it auto-hides when permission is subsequently granted
- Contains no interactive button (linking to System Settings is not reliably cross-platform) — copy only (D-05 from CONTEXT.md)
- Background: `bg-brand/5` with `border border-brand/20 rounded-lg p-3`
- Icon: lucide `Info` 14px `text-brand`

### Permission request trigger

- Triggered when user changes poll frequency from "off" to any active interval (D-04)
- No modal — native OS permission dialog fires automatically via tauri-plugin-notification
- No UI changes during permission request; UI updates reactively after response

## Accessibility Notes

- All Switch components must have `aria-label` or associated `<label>` pointing to the switch id
- Weekday pill buttons use `aria-pressed` (boolean)
- Permission banner uses `role="status"` so screen readers announce it when it appears
- Time inputs: associate with `<label>` elements using `htmlFor`/`id`
- Minimum touch target: 44px height on all interactive controls (time inputs, weekday pills, switches)
