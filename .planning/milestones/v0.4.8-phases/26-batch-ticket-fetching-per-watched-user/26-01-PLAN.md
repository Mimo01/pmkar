<objective>
Refactor `handleFetch()` in `TicketListPage.tsx` from a single combined JQL request into a sequential per-user batch loop. The "mine" batch runs first using `assignee = "<user>" OR issueKey in watchedIssues()`; one batch per watched user follows using `assignee = "<identifier>"`. Results are merged with first-seen-wins deduplication, then committed to the store in a single `setTickets()` call. A live progress counter ("X/N users fetched") renders alongside the existing spinner; per-user fetch failures are tolerated and surfaced as a yellow warning listing the failed users by display name.

Purpose: Eliminate the single oversized JQL that times out for users with many watched accounts (Phase 26 goal). Drop expensive `comment ~` / `description ~` clauses per D-02.

Output: Modified `TicketListPage.tsx` with two targeted JQL builders + sequential batch loop + progress counter and partial-failure JSX; extended `TicketListPage.handleFetch.test.tsx` covering multi-batch invocations, dedup, partial failure, and preset fast-paths; two new i18n keys in EN + SK.
</objective>
