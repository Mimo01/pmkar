### Goal of this file

Create `src-tauri/tests/copy_ticket_v2_integration.rs` that proves:
1. **CUTV-02:** Each of the five `copy_pipeline` helpers (`add_remote_link`, `copy_attachments`, `copy_comments`, `copy_worklogs`, `copy_subtasks`) succeeds end-to-end against the mock servers when invoked through a populated `CopyContext`.
2. **CUTV-04:** Setting `CopyContext.target_project_key = "ACME"` (a non-MYPROJ key) still drives the full pipeline. If any production code path still contains a hardcoded `"MYPROJ"` literal, this test will fail because the create-issue body and remote-link payload would carry `"ACME"` while the helper internally substitutes `"MYPROJ"` — surfacing as either an HTTP error or a mismatched assertion.

This is a **direct function-call integration test** (the analog `probe_createmeta.rs` pattern), NOT a Tauri IPC test. We instantiate `CopyContext` directly, build an `audited` client backed by an in-memory `AuditDb`, and call the helpers individually then assert on each `CopyStepResult`.

async fn create_target_issue(ctx: &CopyContext) -> String {
    let body = serde_json::json!({
        "fields": {
            "summary": "Test target issue (CUTV integration)",
            "project": { "key": ctx.target_project_key }, // "ACME" — CUTV-04
            "issuetype": { "id": "10001" }

    let resp = ctx
        .client
        .post(format!("{}/rest/api/3/issue", ctx.target_base_url))
        .header("Authorization", &ctx.cloud_auth)
        .header("Content-Type", "application/json")
        .body(serde_json::to_string(&body).unwrap())
        .send()
        .await
        .expect("create target issue must not error at the network layer");
    assert!(
        resp.status().is_success(),
        "Create target issue returned status {}",
        resp.status()

    let json: serde_json::Value = resp.json().await.expect("create response must be JSON");

}
