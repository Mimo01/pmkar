## v0.4.0 Requirements — All Complete

### Field Discovery

- [x] **DISC-01**: User can fetch field schemas from source Jira Server v2 including custom fields with type detection _(Phase 17, plan 17-04)_
- [x] **DISC-02**: User can fetch field schemas from target Jira Cloud v3 including custom fields with type detection _(Phase 17, plan 17-04)_
- [x] **DISC-03**: System fetches target required-field metadata per (project, issue type) via paginated `createmeta/{key}/issuetypes/{id}` endpoint _(Phase 17, plan 17-04)_
- [x] **DISC-04**: Mock Jira server exposes realistic field schemas including ≥4 custom fields (number, multi-select, user, date) covering renderer registry _(Phase 17, plan 17-01)_ — **Note:** 3 human verification items deferred (probe banner visual, status pill rendering, per-session dismiss/restart cycle)
- [x] **DISC-05**: User can manually refresh the schema cache via a button in Settings _(Phase 21, plan 21-03)_

### Translation Layer (v2 → v3)

- [x] **TRAN-01**: System translates source user values (Server `name`/`key`) to target Cloud `accountId` for person fields _(Phase 18, plan 18-03)_
- [x] **TRAN-02**: System translates wiki markup to ADF for text and multi-line text fields _(Phase 18, plan 18-04)_
- [x] **TRAN-03**: System translates source version names to target Cloud version IDs by name lookup _(Phase 18, plan 18-02)_
- [x] **TRAN-04**: System translates source component names to target Cloud component IDs by name lookup _(Phase 18, plan 18-02)_
- [x] **TRAN-05**: System fills documented htmltoadf coverage gaps (links, blockquotes, mentions, hard-break, mediaSingle) _(Phase 18, plan 18-04)_ — **Note:** Human spot-check recommended for production ADF quality
- [x] **TRAN-06**: System batches user lookups in a single pass to avoid N×M HTTP calls during a copy _(Phase 18, plan 18-03)_

### Mapping Persistence

- [x] **MAP-01**: User has a single global source→target field mapping persisted in a separate `mapping.db` SQLite database _(Phase 19, plan 19-01)_
- [x] **MAP-02**: System ships sensible default mappings on first run (description, labels, priority, assignee, reporter) _(Phase 19, plan 19-01)_
- [x] **MAP-03**: User can add custom-field mappings on top of the defaults _(Phase 21, plan 21-02)_
- [x] **MAP-04**: User can edit or remove any default mapping _(Phase 21, plan 21-02)_
- [x] **MAP-05**: System warns user when a saved mapping references a target field that no longer exists in the schema (drift detection via schema hashes) _(Phase 21, plan 21-02)_

### Field-Type Controls

- [x] **CTRL-01**: User sees a target control matching the field type for: text, multi-line text, URL _(Phase 20, plan 20-03)_
- [x] **CTRL-02**: User sees a target control matching the field type for: single user, multi user, group _(Phase 20, plan 20-04)_
- [x] **CTRL-03**: User sees a target control matching the field type for: single select, multi select, labels _(Phase 20, plan 20-04)_
- [x] **CTRL-04**: User sees a target control matching the field type for: components, versions _(Phase 20, plan 20-04)_
- [x] **CTRL-05**: User sees a target control matching the field type for: date, datetime, number _(Phase 20, plan 20-03)_
- [x] **CTRL-06**: User sees a target control matching the field type for: checkboxes, radio _(Phase 20, plan 20-03)_
- [x] **CTRL-07**: User sees a read-only "Unsupported type" pill when a target field type is not in the renderer registry _(Phase 20, plan 20-03)_
- [x] **CTRL-08**: User combobox/picker performance does not degrade with 5,000+ items (virtualized rendering) _(Phase 20, plan 20-02)_ — **Note:** Human browser observation recommended for 500+ item confirmation

### Mapping Editor (Settings)

- [x] **EDIT-01**: User can open a "Field Mapping" section in Settings showing the current mapping _(Phase 21, plan 21-03)_
- [x] **EDIT-02**: User sees heuristic name-match suggestions for unmapped source fields _(Phase 21, plan 21-02)_
- [x] **EDIT-03**: User can save mapping changes; changes persist across app restarts _(Phase 21, plan 21-02)_

### Person Picker

- [x] **PERS-01**: Person picker is always visible in person and multi-person fields, even when an exact-email match is found _(Phase 22, plan 22-04)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **PERS-02**: Person picker pre-fills the target user when the source user's email exactly matches a target user _(Phase 22, plan 22-04; bug B-05 fix commit 78adcc4)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **PERS-03**: User can search target users by name or email in the picker (reuses Phase 16 search infra) _(Phase 22, plan 22-04)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **PERS-04**: User sees the picker with no pre-fill (and no error) when source has no email due to Cloud privacy mode _(Phase 22, plan 22-04)_ — Code confirmed wired; VERIFICATION.md deferred

### Per-Copy Override + Required-Field Gating

- [x] **OVRD-01**: User picks the target issue type at copy time, defaulting to the source-name match _(Phase 22, plans 22-01/02)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **OVRD-02**: System re-evaluates required-field gating when the user changes the target issue type _(Phase 22, plans 22-01/03)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **OVRD-03**: User can override the saved mapping inline in the Copy Preview without mutating saved config _(Phase 22, plans 22-01/04; fix commit 822d787)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **OVRD-04**: Copy button is disabled until all target-required fields have values _(Phase 22, plans 22-03/04; bug B-01 fix applied)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **OVRD-05**: System surfaces required-but-unmapped target fields inline in the Copy Preview with a clear "fill in or map" affordance _(Phase 22, plans 22-03/04)_ — Code confirmed wired; VERIFICATION.md deferred
- [x] **OVRD-06**: Per-copy overrides do not persist after the Copy Preview modal closes (in-memory only) _(Phase 22, plans 22-01/04)_ — Code confirmed wired; VERIFICATION.md deferred

### Cutover + Audit + Tech Debt

- [x] **CUTV-01**: A new `copy_ticket_v2` Tauri command consumes the mapping engine end-to-end and replaces the existing `copy_ticket` call site _(Phase 23, plan 23-03)_
- [x] **CUTV-02**: Existing copy paths for comments, attachments, worklogs, sub-tasks, and origin remote link continue to work after cutover (full-pipeline integration test passes) _(Phase 23, plan 23-04)_
- [x] **CUTV-03**: System logs each mapping decision, override, and required-gap fill to the audit log with PII/credential redaction (hash-based default, opt-in verbose mode) _(Phase 23, plans 23-02/03)_
- [x] **CUTV-04**: System parameterizes the previously-hardcoded `MYPROJ` cloud project key (carries v0.1.0 INT-02 debt forward) _(Phase 23, plans 23-03/04)_
