# Phase 35 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 35 is frontend logic only (shared `triageActions.ts` + call-site migration). The only NEW user-visible surface is the **Deny Undo toast** and the **error toasts**. ## Interaction Contract

**Deny toast (RTRI-02, RTRI-03)**
- Trigger: successful `set_triage_state('ignored')` after `denyTicket(key)`. Not shown on IPC failure (D-05).
- Message + single action button "Undo". `duration: 8000` ms (D-01). Hover/focus pauses dismissal (sonner default); keep it.
- Toast is global, not tied to route; do NOT dismiss on navigation (D-02). Use a stable toast id per key (e.g. `deny-{KEY}`) so repeated denies replace rather than stack.
- Undo click calls `linkTicket`-equivalent re-link (`relink_ticket`); on success store returns to `copied` with same key, toast dismissed. No success toast (the state change is the feedback).
- Undo failure or `None`: `toast.error` with undo-failed copy; ticket stays in Ignored (D-03).
- Accessibility: sonner toasts are `aria-live` polite; the 8 s duration is the screen-reader allowance. Undo must be keyboard reachable (sonner hotkey Alt+T focuses the region; do not disable).

**Link (RLNK-01/02)**: no new visual. `needs-copy` result opens the existing copy preview exactly as today. `relinked` result has no toast and no navigation; the ticket simply appears Linked.

**Restore / Mark handled**: unchanged visually; failures show the existing error toast pattern (`ignored.restoreFailed` style).

**Constraints (project feedback):** no drag and drop; no hover-revealed icons introduced; one entry point per action; no Jira call on Deny.

## Copywriting Contract

Only strings that must exist for Phase 35. Keys are proposals (planner may rename, keep the `triage.` namespace). Phase 36 owns all other strings. Slovak uses "tiket", never "úloha" (guard test enforces).

| Element | EN | SK |
|---------|----|----|
| Deny toast message (`triage.denied`) | Moved {KEY} to Ignored. | Tiket {KEY} presunutý do Ignorované. |
| Undo action (`triage.undo`) | Undo | Späť |
| Error: deny failed (`triage.denyFailed`) | Could not move the ticket to Ignored. Try again. | Tiket sa nepodarilo presunúť do Ignorované. Skúste to znova. |
| Error: undo failed (`triage.undoFailed`) | Could not restore the link to {KEY}. The ticket stays in Ignored. | Odkaz na {KEY} sa nepodarilo obnoviť. Tiket zostáva v Ignorované. |
| Error: link failed (`triage.linkFailed`) | Could not link the ticket. Try again. | Tiket sa nepodarilo prepojiť. Skúste to znova. |
| Error: restore failed | reuse existing `ignored.restoreFailed` | reuse existing |
| Primary CTA | none new this phase (Phase 36 adds labelled Deny / Link buttons) | - |
| Empty state | not applicable (no new screens) | - |
| Destructive confirmation | none: Deny is reversible via Undo and the Ignored tab; no Cloud delete | - |

The user-facing tab is currently labelled "Ignored" (`nav.ignored`, SK "Ignorované"); strings above use that label. If Phase 36 renames the tab to "Not mine", it updates these strings. Add keys to both `en.json` and `sk.json` so i18n guard tests pass.
