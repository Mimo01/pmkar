| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between subheading text and count; icon gaps |
| sm | 8px | Gap between hint line and Remove button; popover button gap (`gap-2`) |
| md | 16px | Popover padding (`p-4`); subheading horizontal padding (`px-4`, matches list rows) |
| lg | 24px | Space above the missing block subheading (`pt-6` equivalent) |
| xl | 32px | unused |
| 2xl | 48px | unused |

Exceptions: popover width `w-70` (280px) reused from SelectionBar remove popover; subheading row min-height 40px to match the filter bar density; Remove buttons use `size="sm"` (h-8) and must not shrink below 32px height. Existing code uses 2px/6px/10px micro-values in cards (`py-0.5`, `px-1.5`); do not introduce new off-scale values in new code.

## Color

Existing tokens only (`src/index.css`, light and dark).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-brand-bg` #f7f7f8 / dark #161617 | Page background |
| Secondary (30%) | `--color-brand-surface` #fff / dark #1e1e20; border `--color-brand-border` | Cards, popovers |
| Accent (10%) | `--color-brand` #c02232 | Not newly used in this phase (see below) |
| Destructive | `--color-destructive` #dc2626 | Popover confirm "Remove" buttons only |

Accent reserved for: existing focus ring (`--color-ring`) on the new buttons. No new accent usage. Missing state is conveyed by dimming and text, never by color alone.

Missing-card treatment:
- Card content (key, summary, status, chips text, meta) wrapped in `opacity-60`. Do NOT apply opacity to the whole card root, so the controls stay full contrast.
- Hint line text: `text-brand-text-secondary` (#5c585a on white = about 7:1; dark #95959a on #1e1e20 = about 5.6:1), both pass AA 4.5:1. Do not use `text-brand-muted` for the hint (#8c8c92 on white is about 3.3:1, fails AA).
- "Remove" and "Remove all missing" buttons: `Button variant="outline" size="sm"` at full opacity, text `text-brand-text`.
- Confirm button in popovers: `variant="destructive" size="sm" className="text-white"` (same as SelectionBar).
- Dimmed content must still meet 3:1 for large/non-text and remain legible; the executor must verify the summary at opacity-60 is not relied on for required information (status text is also visible in the chip). Final contrast verification is Phase 33 (GQA-02).

## Layout and Interaction Contract

### Missing block (D-03, D-04, D-08)
1. Group list renders present members in the chosen sort, then (only when at least one member is flagged missing) the missing block.
2. Block starts with a subheading row, `role="group"` with `aria-labelledby` pointing at the heading text: left "No longer in results (N)" (12px, 600, `text-brand-text-secondary`), right the "Remove all missing" outline sm button. Row has a top border (`border-t border-brand-border`) and `bg-brand-surface-raised` is NOT used (keep flat).
3. Missing members use the same sort and the same search/filter as present ones. The subheading and its count N reflect the visible (filtered) missing members. "Remove all missing" acts on all missing members of the group, so if a filter hides some, the confirmation popover uses the group-wide count. The menu item count is also group-wide. If the filter hides every missing member, the subheading is hidden but the menu item remains.
4. Tab count includes missing members (unchanged).

### Missing card (D-05, D-07)
- Card remains fully clickable and keyboard-activatable; opens detail as today.
- Content dimmed (`opacity-60`); controls (selection checkbox in select mode, chips, Remove) not dimmed.
- Below the card content, one row: left hint "No longer in results" (12px, 400, `text-brand-text-secondary`), right labelled "Remove" outline sm button. Rendered via the existing card `actionSlot`/sibling-controls area; always visible (never hover-revealed). Remove button must not be nested inside the stretched card button (sibling control, stops propagation).
- Status shown is the last-seen snapshot status (may be stale, accepted, no extra label).
- Remove button accessible name: "Remove {KEY} from {group}" via `aria-label`; visible text "Remove".
- Select mode: missing cards selectable like any card; the per-card Remove stays visible.

### Per-card Remove confirmation (D-06)
- Popover anchored to the card Remove button, `side="top"` fallback auto-flip, width `w-70`, `p-4`.
- Question 14px/600 `mb-3`; row `flex justify-end gap-2`: Cancel (outline sm) then Remove (destructive sm).
- Initial focus on Cancel (as SelectionBar). Esc closes; focus returns to the trigger Remove button. If the card disappears after confirm, focus moves to the next card's stretched button, or to the subheading Remove-all button if present, otherwise to the list container.
- On failure: sonner `toast.error` using the Phase 30/31 error pattern; popover closes, member stays.
- On success: card disappears; no toast required for single remove (matches Phase 31 chip ×). Optional polite live-region announcement via existing status region.

### Remove all missing (D-09, D-10, D-11)
- Entry point 1: subheading button "Remove all missing" (visible text without count; the count is in the heading).
- Entry point 2: group `…` menu item "Remove all missing (N)", placed directly above `Delete group…`, with a separator logic unchanged. Hidden (not disabled) when there are no missing members or hints are gated off.
- Popover (anchored to subheading button, or to the group tab when from the menu, like Rename): "Remove N issues from ‘{group}’? They are no longer in results." Cancel / Remove (destructive). Initial focus on Cancel; focus returns to the trigger (for menu origin: the group tab).
- One atomic `removeMembers` call; success: sonner `toast.success` "Removed N issues from ‘{group}’"; failure: `toast.error`, nothing removed.

### Gating of all hint UI (D-12 to D-14)
Dim, hint, Remove, subheading and menu item render only when: a fully successful fetch has completed this session for the current query (all batches ok, not truncated, no error) AND the query (preset / custom JQL) has not changed since. Otherwise all members render undimmed from snapshots with none of the above controls. No loading or "checking" indicator is shown for this state.

### Empty/edge states
- All members missing and all removed: group falls to the existing group empty state.
- Missing block with zero filter matches: block hidden; existing "no results" state applies only if the whole list is empty.

## Accessibility

- Hint text and Remove buttons at full contrast, AA 4.5:1 in light and dark (see Color).
- Dimming is never the only signal: visible hint text plus the subheading.
- Subheading is a real heading element (`h3`-level, visually 12px) for screen reader navigation.
- All new controls keyboard reachable in DOM order after the card's main button; visible focus ring (`--color-ring`).
- Respect `motion-reduce` for any opacity transitions (`transition-opacity duration-150 motion-reduce:transition-none`).
- No drag and drop; no hover-only controls.
