  <action>
    Add `pub fn refresh_snapshots(&self, scope: &str, items: &[NewMember]) -> GroupResult<usize>` to `impl GroupsDb`, directly after `remove_members`. Per D-15 it is UPDATE-only: first validate every item exactly as `add_members` does (`is_valid_issue_key` -> `GroupErrorCode::InvalidIssueKey`; `serde_json::from_str::<serde_json::Value>` must be `Value::Object` -> `GroupErrorCode::InvalidTicket`), returning early before any write. Do NOT call `ensure_group_in_scope` (no group id). Then take `chrono::Utc::now().to_rfc3339()`, open `self.conn.unchecked_transaction()`, and for each item run the parameterised statement `UPDATE issue_snapshot SET ticket_json = ?3, updated_at = ?4 WHERE scope = ?1 AND issue_key = ?2 AND ticket_json != ?3` via `params![scope, item.issue_key, item.ticket_json, now]`, summing affected rows; commit and return the sum. Never use `INSERT ... ON CONFLICT` here (it would create orphan snapshots with no membership, bypassing GC). Do not call `gc_snapshots` (nothing is deleted). Add a doc comment stating "Refresh stored snapshots of existing members only (D-15). Never inserts, never deletes, never touches group_member."
    Add the tests listed in <behavior> to the existing `mod tests`, reusing `new_db()`, `S`, `member()`, `snapshot_count()`; for a second scope use any other scope string literal. For changed JSON build a JSON object string that differs from `member()`'s default (read `member()` to see its shape). Leave existing tests `remove_members_gcs_snapshots` and `fk_cascade` unchanged; they already cover delete_group GC and retention while referenced (D-16) and must still pass.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Tampering | refresh_snapshots SQL | mitigate | rusqlite `params!` only; no string-built SQL |
| T-32-02 | Tampering / Elevation | cross-scope overwrite | mitigate | scope derived in Rust via `require_scope`; every UPDATE has `WHERE scope = ?1`; test refresh_snapshots_scope_isolated |
| T-32-03 | Tampering | malformed payload | mitigate | validate every key with `is_valid_issue_key` and every ticket_json as a JSON object before opening the transaction; test refresh_snapshots_rejects_invalid_input |
| T-32-04 | Integrity (data loss) | membership | mitigate | UPDATE-only on issue_snapshot, no group_member writes; test refresh_snapshots_never_changes_membership (GDUR-01) |
| T-32-05 | Denial of Service | large payload | accept | frontend sends only member tickets (plan 32-04); single local transaction; desktop single-user app |
</threat_model>
