<objective>
Close verification gap CR-01: snapshot refresh after a manual fetch must never write one server's ticket JSON into another server's group snapshots.

Purpose: GDUR-06 says snapshots refresh after each successful fetch. Today `handleFetch` captures `fetchSig` at fetch start but calls `refreshSnapshots(...)` after the await without checking it, and Rust derives the scope at call time. A server switch during an in-flight fetch can therefore persist server A's data over server B's snapshots when issue keys collide. This plan adds a frontend guard (signature must be unchanged) plus a Rust guard (expected scope must match the current scope).
Output: Rust command with an `expected_base_url` check and cargo tests, `groupStore.refreshSnapshots` forwarding the base URL, gated calls in TicketListPage, vitest coverage.

Deferred on purpose (not part of this gap): gating `store.setTickets` on the signature. It is session-only (not persisted). The existing test "preset changed mid-flight stores the fetch-start signature" locks in the current fetch-start semantics for it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| async fetch result -> persisted SQLite snapshots | Jira data fetched under one connection crosses into storage that is scoped to whichever connection is current at write time |
| JS -> Rust IPC (refresh_group_snapshots) | expectedBaseUrl is caller-supplied, and Rust treats it only as a narrowing check, never as a write scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-25 | Tampering (cross-scope data corruption) | TicketListPage.handleFetch refresh | mitigate | Recompute the signature after the await, and refresh only when it equals the fetch-start fetchSig (isFetchStillCurrent) |
| T-32-26 | Tampering (TOCTOU between JS check and Rust write) | refresh_group_snapshots_inner | mitigate | Compare normalize_scope(expected_base_url) to require_scope(); on mismatch return Ok(0) without writing |
| T-32-27 | Elevation (caller picks the write scope) | refresh_group_snapshots | mitigate | The write scope is still derived in Rust from connection meta. expectedBaseUrl can only veto a write, never redirect one |
| T-32-28 | Denial (snapshots skip a refresh after a mid-flight filter change) | handleFetch | accept | Snapshots stay at the previous fetch's values, nothing is removed (GDUR-01), and the next fetch refreshes them |
</threat_model>
