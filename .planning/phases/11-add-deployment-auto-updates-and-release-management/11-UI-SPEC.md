## States and Interactions

### About / Updates section — state machine

| State | Visual |
|-------|--------|
| idle (never checked) | Version string + "Check for updates" button enabled. Last checked: "Never" |
| checking | "Check for updates" button disabled, shows Skeleton in place of result, or spinner inside button |
| up-to-date | Version string + green checkmark icon (Lucide `CircleCheck` w-4 h-4 text-green-500) + "Up to date" text + timestamp |
| update-available | Version string + update badge (accent) + "Update Now" button — triggers modal |
| error | Error message text in text-red-400 + "Try again" link |

### Update modal — state machine

| State | Visual |
|-------|--------|
| available | Changelog visible, "Update Now" / "Later" buttons enabled |
| downloading | Progress bar 0–100%, buttons disabled, label "Downloading update..." |
| installing | Progress bar at 100%, label "Installing...", buttons disabled |
| complete | App relaunches automatically — modal dismissed by app restart |
| error | Error message + "Later" button re-enabled, "Try again" replaces "Update Now" |

### Keyboard and accessibility requirements

- Modal must trap focus (shadcn Dialog provides this via Radix)
- "Later" button must be focusable and activatable via Escape key (shadcn Dialog default close — override: do not close on Escape during download/install states)
- "Check for updates" button must have `aria-busy="true"` during checking state
- Progress bar must use `role="progressbar"` with `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"` (shadcn Progress provides this)
- Update modal status changes must be announced via `aria-live="polite"` region
