# Phase 37.2 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** New main category **Watched** (triage state `watched`, nav label "Watched" EN / "Sledované" SK) beside New, Dismissed (`ignored`, SK "Zamietnuté") and Linked (`copied`). New nav page, new **Watch** button, extended action sets per state, two new confirm-dialog variants, Undo toasts for Declined to/from Watched, hint extension. No new colors, sizes, tokens, icons or primitives.

Sources: 37.2-CONTEXT.md (D-01..D-12, locked), 37.1-UI-SPEC.md (dialog contract, tokens, copy pattern), `ConfirmTransitionDialog.tsx`, `RememberedLinkHint.tsx`, `IgnoredTicketsPage.tsx`, `AppShell.tsx`, `src/index.css`, `en.json`/`sk.json`. Project feedback: explicit labelled buttons only (no hover icons, one entry point per action), no drag and drop, SK says "tiket" never "úloha". Items marked (default) were chosen by the researcher within Claude's Discretion.

## Interaction Contract

### Navigation and pages (D-01, D-02)

| Item | Contract |
|------|----------|
| Nav tab | Add `{ id: 'watched', label: t('nav.watched') }` in `AppShell.tsx` as the **last** tab (after `linked`) so existing tab positions do not shift (default). Count badge as on siblings |
| Watched page | Copy of `IgnoredTicketsPage` table: same columns (Key, Summary, Status, Priority, Assignee, Updated, Actions), same sorting, loading and row-click-opens-detail behaviour. Heading `watched.heading`. Rows: `RememberedLinkHint variant="row"` beside key/summary where a key is remembered; Actions column holds one labelled button **Restore** (to seen). No Watch/Link/Deny in rows (detail only) |
| Main list / counts | Watched tickets are excluded from New/Seen lists and from unread/new counts, same as Dismissed. Fetch/poll never mutate a Watched row |
| Empty state | Heading + body (see Copywriting); no CTA button (Watch is done from a ticket's detail); body names the entry point in text |

### Button sets per state in detail page, panel and group view (D-09)

All buttons: `variant="outline"`, `size="sm"`, labelled text, same row and order rules as existing Deny/Link row. The new **Watch** button sits immediately after Deny where Deny exists, otherwise after the Link button.

| State | Buttons (left to right) |
|-------|-------------------------|
| Linked | Deny, **Watch** |
| Dismissed | Link / "Restore link to KEY", **Watch**, Restore to seen |
| Watched | Link / "Restore link to KEY", Deny, Restore to seen |
| New / Seen | unchanged (Watch is not offered; Watched is reached only from Linked or Dismissed per roadmap) |

Remembered-key hint: `RememberedLinkHint` must render for `ignored` **and** `watched` entries with `copiedKey` (replace the `state === 'ignored'` condition), always visible text under the button row (detail) and inline (row). Not tooltip-only. Existing tooltip on "Restore link to KEY" may remain as supplementary.

### Transition matrix

| From to | Confirm dialog | Undo toast | Result announcement |
|---------|----------------|------------|---------------------|
| Linked to Watched | Yes, `watch` variant | No | `a11y.watched` |
| Watched to Linked (key remembered) | Yes, `restore` variant (reuses 37.1 `link` variant copy; title "Restore link to KEY?") then `relink_ticket` | No | `a11y.linked` |
| Watched to Linked (never linked) | No dialog; opens copy preview (its own confirmation, D-06) | No | existing copy flow |
| Dismissed to Watched | No (default, D-05) | Yes, 8 s | `a11y.watched` |
| Watched to Dismissed | No (default, D-05) | Yes, 8 s | `a11y.denied` |
| Watched to seen / Dismissed to seen | No | No (existing) | `a11y.restored` |
| Linked to Dismissed | Yes, existing `deny` variant | No | existing |
| Dismissed to Linked (key) | Yes, existing `link` variant | No | existing |

Undo rules (D-10): Undo restores the exact prior state (Dismissed to Watched undo returns to Dismissed; Watched to Dismissed undo returns to Watched), preserves `copiedKey`, and can never produce Linked for a never-linked ticket (CONF-03). Toast duration and placement match the Deny toast (sonner, global, ~8 s). Undo failure reuses a toast in the pattern of `triage.undoFailed` (new key, see Copywriting).

### Confirm dialog (extends `ConfirmTransitionDialog`, structure unchanged from 37.1)

Reuse everything in 37.1-UI-SPEC "Dialog structure": `role="alertdialog"`, `hideClose`, `max-w-[400px] p-6 bg-popover border-brand-border`, initial focus on **Cancel**, Esc/Cancel close with no write, outside click does not dismiss, Esc does not close the surrounding panel, snapshot ref for close animation, busy ref against double submit, single instance, stale guard on Confirm (Watch requires state still `copied`; restore requires still `watched` with the same remembered key; otherwise close silently). Add one new variant `watch`; the Watched to Linked move reuses the existing `link` variant (key, cloudKey) with the source tab irrelevant to its copy. No announcement on open/cancel. Nothing is written before Confirm.

### Focus (D-12, Phase 36 D-05)

| Action completed | Focus moves to |
|------------------|----------------|
| Watch (confirmed or instant) | The new state's primary action: "Restore link to KEY" if key remembered, else Link/Copy |
| Watched to Dismissed | Link / "Restore link to KEY" button (primary in Dismissed set) |
| Watched or Dismissed to Linked | Linked badge (existing rule) |
| Restore to seen | Existing behaviour |
| Dialog Cancel/Esc | The trigger button (Watch button ref, or Link/Restore ref) |
| Row Restore on Watched page | Next row's Restore button, else previous row's, else page heading (same as Dismissed page) |

Focus must never fall to `<body>` when the activated button unmounts. WebView2 checklist gains: Watch dialog Cancel focus, focus after each transition, Undo toast keyboard reachability, live-region announcements for all transitions.
