## Summary

Watched is a fifth stored value in `triage_state.state` (`new, seen, ignored, copied, handled, watched`). Every layer already has a precedent: `handled` was added by a CHECK-widening table rebuild (`triage_db.rs`), the Rust whitelist `validate_triage_state`, the TS `TriageState` union, and list predicates in `ticketListUtils.ts`. `copied_key` survives all transitions because `set_triage` upserts only `state`/`last_updated`, and `applyState` copies `prev.copiedKey` optimistically. `relink` flips any state with a non-null `copied_key` to `copied`, so Watched -> Linked needs no Rust change beyond the CHECK/whitelist. `ensure_not_linked` blocks copying whenever `copied_key` exists, so Watched can never create a duplicate copy. [VERIFIED: codebase read of triage_db.rs, commands.rs, triageActions.ts]

The frontend work is mostly (a) a new predicate `isWatchedCandidate` and exclusions in `isNewCandidate`, (b) a new page cloned from `IgnoredTicketsPage`, (c) new tab in `AppShell`/`CoreTab`/`App.tsx`, (d) new actions `watchTicket` + Undo, (e) extending `useTriageDetailActions` with `isWatched`, `requestWatch`, `rememberedKey` for Watched, and a `watch` dialog variant, and (f) three detail surfaces (`TicketDetailPage`, `TicketDetailPanel`, group view) which currently duplicate the button branching and must each get the Watched branch.

**Primary recommendation:** Do it in 4 waves: (1) Rust+types+predicates+groupBadge (foundation, tested), (2) `triageActions` + hook + dialog variant + guard tests, (3) page/nav/detail/group UI, (4) i18n + a11y + mock fixtures + UAT checklist. Reuse everything; add no packages.

### Anti-Patterns
- Calling `invoke('set_triage_state')` from a component (breaks transitionGuard and single-writer rule).
- Writing a `copied` entry in the store for a Watched -> Linked move before `relink_ticket` returns; use the DB-returned key only.
- Letting Undo call `relink_ticket` for a non-`copied` prior state.
- Adding hover icons / drag and drop (project feedback).

## Common Pitfalls

1. **Group badge falls through to "done"** for Watched members (see groupBadge). Add test in `groupBadge.test.ts`.
2. **Duplicate Copy button** on Watched detail because the "not linked/denied/handled" guards omit watched (Page and Panel).
3. **Migration sentinel**: keying on `'handled'` would skip rebuilding 5-value DBs. Sentinel must be `'watched'`. Add a migration test from the 5-value shape (the existing legacy helper builds the 4-value shape; add a 5-value variant).
4. **Undo mis-routing**: `undoDeny` checks `state==='ignored'`; reusing it for Watched -> Dismissed Undo would no-op. Write separate guarded undos; keep rule "relink only when prior state was `copied`".
5. **`denyTicket` toast only when key remembered**: D-10 wants Undo for never-linked Declined <-> Watched too.
6. **`restoreTicket` on Watched must go to `seen`** (no relink). Dismissed page Restore keeps relinking when a key exists (existing behaviour).
7. **Stale guards in `onResolve`**: the existing `link` branch demands `ignored`; with Watched it must accept `watched` with the same remembered key. A missed edit leaves Watched -> Linked always "stale".
8. **Focus loss**: Watch/Deny/Restore buttons unmount on state change; set `pendingFocus` before the await (pattern in `handleDeny`) and map new targets; Panel Esc behavior with open dialog already handled via `confirmOpen`.
9. **`handled` state interaction**: `handled` rows appear in the Dismissed page and have a separate detail branch. Watch is not offered from `handled` (spec: only Linked or Declined). Do not accidentally offer it.
10. **Naming collision** with "watched users" settings and `WatchedUser` in `poll_engine.rs` / `triage_db.rs`; use `watched` only for the triage state in new code, and name the page component `WatchedTicketsPage` and predicate `isWatchedCandidate`. Do not grep-and-replace.
11. **Live-region double announce / SK grammar**: UI-SPEC grammar note: check "Presunúť do {{tab}}" with "Sledované" (should be locative/accusative "Sledovaných"); prefer literal "Sledovaných" in SK title/action and "Zamietnutých" for Dismissed.

## Code Examples

Migration sentinel (adapt existing code in `triage_db.rs`):
```rust
if !existing_sql.contains("'watched'") {
    conn.execute_batch(MIGRATE_TRIAGE_CHECK_WATCHED)?; // CHECK(state IN ('new','seen','ignored','copied','handled','watched'))
}
```

Watch action (pattern from `denyTicket`, `triageActions.ts`):
```ts
export async function watchTicket(issueKey: string): Promise<boolean> {
  const { ok, prev } = await applyState(issueKey, 'watched', 'triage.watchFailed');
  if (!ok) return false;
  announce(i18n.t('a11y.watched', { key: issueKey }));
  if (prev?.state === 'ignored') {
    toast(i18n.t('triage.watched', { key: issueKey }), {
      id: `watch-${issueKey}`, duration: UNDO_TOAST_MS,
      action: { label: i18n.t('triage.undo'), onClick: () => void undoWatch(issueKey, 'ignored') },
    });
  }
  return true;
}
```
`undoWatch` guards `triageMap[key]?.state === 'watched'`, restores via `applyState(key, priorState, ...)` only (never relink).
