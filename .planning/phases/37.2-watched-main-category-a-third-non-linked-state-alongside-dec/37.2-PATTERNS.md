## Shared Patterns

### Single-writer optimistic transition
**Source:** `T/triageActions.ts` `applyState` l.40-85. All new transitions use it; `copiedKey: prev?.copiedKey ?? null` preserves the remembered key. Never `invoke('set_triage_state' | 'relink_ticket')` outside this file (guard test).

### Announce + toast
`announce(i18n.t('a11y.*', { key }))` for every transition; `notifyError` for failures; Undo toast `UNDO_TOAST_MS = 8000`, id convention `deny-${key}` / `watch-${key}`.

### Confirm-before-Linked-change
**Source:** `useTriageDetailActions` `openConfirm`/`onResolve` + `ConfirmTransitionDialog`. Nothing written before Confirm; stale guard calls `notifyStale`. Only Linked <-> Watched uses it; Declined <-> Watched is instant + Undo.

### Focus on unmount
`pendingFocus.current = 'primary'` set BEFORE the awaited action (see `handleDeny` l.108-112); effect re-focuses when the target ref is connected.

### Predicate-driven membership
New list excludes `watched` (`isNewCandidate`), `newCount` counts only `state==='new'` (ticketStore, add test), group badge via `isWatchedCandidate`. Fetch/poll never write triage (existing static test `test_fetch_triage_sync_poll_engine_never_writes_triage`; add Watched-row regression).

### Project rules (MEMORY)
No drag and drop, no hover-revealed icons (explicit labelled buttons), no `?? []` in Zustand selectors, SK uses "tiket".
