# Phase 37.2: Watched main category - Context

**Gathered:** 2026-10-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a new main category **Watched** alongside New, Declined (UI label "Dismissed", triage state `ignored`) and Linked (`copied`). Watched is a parking state: it links nothing. Any Linked or Declined ticket can become Watched; Watched can become Declined, Linked (relinking the remembered Cloud key, never creating a copy) or back to normal (seen). Same confirmation, counts and accessibility rules as the existing transitions (Phases 35-37.1).

</domain>

<decisions>
## Implementation Decisions

### Placement and visibility
- **D-01:** New nav page "Watched" next to Dismissed and Linked, built on the `IgnoredTicketsPage` table pattern, with a count badge. Slovak label "Sledované" (uses "tiket" in all body copy, never "úloha").
- **D-02:** Watched tickets are hidden from the main New/Seen list and from unread/new counts, exactly like Dismissed. Fetch and poll never change a Watched row (extend the 37.1 static guard/regression tests to the new state).
- **D-03:** New triage state `watched`: widen the SQLite CHECK constraint (table rebuild migration like the earlier `handled` widening), TS `TriageState`, and `set_triage` validation. `copied_key` is preserved on every transition in and out of Watched (LINT-01 / D-09 of Phase 35).

### Confirmations
- **D-04:** Confirmation dialog (reuse `ConfirmTransitionDialog`, Cancel focused, alertdialog) for moves that change Linked status: **Linked → Watched** and **Watched → Linked** (with remembered key: "Restore link to KEY", then `relink_ticket`; never a copy).
- **D-05:** No dialog for **Declined → Watched** and **Watched → Declined**; these are instant with an Undo toast (see D-10). The user delegated this split ("you decide"); rationale: only Linked carries real consequences.
- **D-06:** Watched, never linked, → Link goes to the existing copy preview (its own confirmation), same as a never-linked Declined ticket.
- **D-07:** Nothing is written before Confirm; Cancel/Esc leaves the ticket unchanged. Stale-guard behaviour matches `useTriageDetailActions` from 37.1.

### Remembered link
- **D-08:** Reuse `RememberedLinkHint` on Watched rows and detail (always-visible text, not tooltip-only); button label "Restore link to KEY" when a key is remembered.

### Buttons and entry points
- **D-09:** Explicit labelled neutral outlined buttons in detail page, panel and group view (shared detail; no inline `set_triage_state`). Per state:
  - Linked: Deny, **Watch**
  - Declined: Link / Restore link to KEY, **Watch**, Restore to seen
  - Watched: Link / Restore link to KEY, Deny, Restore to seen
  List rows stay detail-only for Watch; Watched page rows keep Restore + hint (no hover icons, one entry point per action).
- **D-10:** Undo toast (~8 s, global, like Deny) for Declined ↔ Watched; Undo restores the true prior state and can never make a never-linked ticket Linked (CONF-03). Confirmed moves get no Undo.
- **D-11:** All transitions go through `triageActions.ts` (add e.g. `watchTicket`, extend `restoreTicket`/`linkTicket`); the transition guard test is extended so only the confirmed hook path calls Linked-affecting functions.

### Accessibility and i18n
- **D-12:** All new strings in EN and SK, passing i18n guards (including groups/"tiket" guard); live-region announcements for every transition; focus never falls to `<body>` when a button unmounts (move to the new primary action, per Phase 36 D-05). WebView2 checklist extended.

### Claude's Discretion
- D-05 confirm/no-confirm split for the Declined↔Watched moves; exact function and i18n key names; focus target details; migration implementation; mock fixtures for Watched scenarios.

</decisions>
