## Interaction Contracts (A11y-Specific)

This phase introduces interaction patterns not covered by the standard spacing/typography/color sections. These are binding contracts for the executor.

### Focus Ring Standard

All interactive elements must use `focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2`. Do not use `focus:ring` (shows on mouse clicks). The ring-offset color inherits from the page background via `ring-offset-background` — no hardcoded color needed.

For elements where ring-offset creates visual overlap (inline items like table rows), use `focus-visible:outline-2 focus-visible:outline-brand focus-visible:outline-offset-[-2px]` (inset outline) instead.

Source: RESEARCH.md Pattern 2 + Claude's Discretion from CONTEXT.md.

### Keyboard Navigation Pattern

**TicketCard (list items, 5-20 items):** Standard `Tab` navigation, not roving tabindex. Each card is an individual tab stop. Rationale: list sizes of 5-20 items do not warrant arrow-key roving tabindex complexity; standard Tab flow satisfies WCAG 2.1 SC 2.1.1.

Implementation: Keep outer TicketCard as `<div role="button" tabIndex={0}>` (not `<button>`) because `actionSlot` may contain nested `<button>` elements (e.g., Restore in IgnoredTicketsPage). Nested `<button>` inside `<button>` is invalid HTML. The `<div role="button">` with `onKeyDown` for Enter/Space is the correct pattern.

```tsx
onKeyDown={(e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); onClick(); }}}
tabIndex={0}
role="button"
aria-label={ticket.fields.summary}
className="... focus-visible:outline-2 focus-visible:outline-brand focus-visible:outline-offset-[-2px]"
```

**AuditLog expandable rows:** `<tr>` gets `tabIndex={0}`, `role="button"`, `aria-expanded`, and `onKeyDown` for Enter/Space.

**TicketDetailPage tabs:** Tab buttons within `role="tablist"` support left/right arrow keys within the tablist; Tab key exits the tablist to the first tabpanel. Add `id` to each tab button and `aria-labelledby` + `tabIndex={0}` to each tabpanel.

Source: RESEARCH.md Pattern 2, Pattern 7 + CONTEXT.md Claude's Discretion.

### Escape Key Behavior

Full-page overlay views (TicketDetailPage, AuditLogPage, SettingsPage): Escape key is NOT intercepted — these are full-page routes, not overlays. Back navigation is via explicit back button (ArrowLeft icon).

Modal overlays (CopyPreviewModal, CopyResultModal): Radix Dialog already handles Escape key — no additional implementation needed.

Source: RESEARCH.md + CONTEXT.md Claude's Discretion.

### Skip-to-Content Link

Not warranted. The app has a minimal nav structure: AppShell header with 3 tabs + 2 icon buttons (5 tab stops before main content). WCAG 2.4.1 (bypass blocks) applies at 3+ repeated navigation items. With only 5 tab stops, a skip link adds complexity without proportionate benefit.

Source: CONTEXT.md Claude's Discretion — Claude evaluates based on tab depth.

### Dynamic Page Titles

Not implemented. The app has 6 distinct views (wizard, settings, ticket list, ticket detail, audit log, ignored list), but as a Tauri desktop app it has no browser URL bar and no multi-tab context. The window title is static ("Pmkar"). The nav landmark and heading hierarchy provide sufficient orientation without dynamic `document.title` changes.

Source: CONTEXT.md Claude's Discretion.

### Live Regions for Async Operations

Two operations require `aria-live` regions that are currently missing:

1. **Copy progress** (`CopyPreviewModal`): `progressStep` text element gets `aria-live="polite" aria-atomic="true"`.
2. **Fetch status** (`TicketListPage`): The loading/error state paragraph gets `aria-live="polite"`.

Do not add `aria-live` to elements already covered: `TestResult.tsx` (already has `role="status"` and `role="alert"`), `SkeletonCards` (already has `aria-busy="true"`).

Source: RESEARCH.md Pattern 6.

## Form Validation Error Pattern

Pattern for all forms: inline error text below the field + `role="alert"` + `aria-describedby` link from input to error.

```
<input aria-invalid={!!error} aria-describedby={error ? "field-error-id" : undefined} />
{error && <p id="field-error-id" role="alert" className="text-xs text-red-400 mt-1">{error}</p>}
```

Required field indicators: asterisk (`*`) in label text + `required` attribute on input. Use this pattern only in ConnectionForm and CopyPreviewModal where fields are truly required. SetupWizard already validates on submission.

Error copy style: "problem description" + "what to do" in one sentence. Example: "Invalid URL — must start with https://" not just "Invalid URL."

Source: RESEARCH.md Pattern 3 + CONTEXT.md Claude's Discretion.
