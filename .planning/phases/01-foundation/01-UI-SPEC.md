# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Scope

Phase 1 is an infrastructure phase. Per CONTEXT.md: "No UI workflows — just the shell, security plumbing, mock server, and audit logging."

The UI surface is limited to:
1. **App shell window** — the Tauri window that proves the scaffold compiles and runs
2. **Dev status screen** — a minimal view showing mock server status and credential store availability (developer-facing, not a user workflow)

All design tokens declared here establish the baseline every subsequent phase inherits. Downstream phases (2–7) will extend this contract; they must not contradict it.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact element spacing, status indicator gaps |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, panel insets |
| xl | 32px | Layout gaps between major zones |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical spacing |

Exceptions: none for Phase 1.

In Tailwind 4, these map to: `p-1` (4px), `p-2` (8px), `p-4` (16px), `p-6` (24px), `p-8` (32px), `p-12` (48px), `p-16` (64px).

## Typography

System font stack: `font-family: ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif`

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm font-normal leading-normal` |
| Label | 12px | 500 (medium) | 1.4 | `text-xs font-medium leading-snug` |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold leading-tight` |
| Display | 28px | 600 (semibold) | 1.2 | `text-2xl font-semibold leading-tight` |

Weights used: 400 (regular) and 600 (semibold). 500 (medium) used only for labels — not a third general weight.

## Color

Phase 1 uses a neutral dark palette appropriate for a developer tool. Both light and dark modes are declared; Tailwind `dark:` variants enforce the split.

| Role | Light Value | Dark Value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `#ffffff` (white) | `#0f172a` (slate-950) | Window background, main surface |
| Secondary (30%) | `#f1f5f9` (slate-100) | `#1e293b` (slate-800) | Status panel background, sidebar, card surfaces |
| Accent (10%) | `#3b82f6` (blue-500) | `#60a5fa` (blue-400) | Active status indicators, primary action buttons |
| Destructive | `#ef4444` (red-500) | `#f87171` (red-400) | Error state text, failure indicators only |

Accent reserved for:
- Mock server "running" status badge
- Primary action button (single instance per view)
- Focus ring on interactive elements

Accent is NOT used for: decorative elements, informational badges, headings, or hover states on non-interactive elements.

Text colors:
- Primary text: `#0f172a` light / `#f8fafc` dark (slate-950 / slate-50)
- Secondary text: `#64748b` light / `#94a3b8` dark (slate-500 / slate-400)
- Disabled text: `#cbd5e1` light / `#475569` dark (slate-200 / slate-600)

## Screen Inventory

Phase 1 delivers one screen:

### Dev Status Screen (`/` — default route)

**Purpose:** Confirms the scaffold is working. Visible only in development builds (`#[cfg(feature = "mock-server")]` flag controls mock start; UI shows only when mock feature is active).

**Layout:** Single centered panel, 480px max-width, vertically centered in the window.

**Elements:**
- App name "pmkar" as Display heading (28px, semibold)
- Subtitle "Development scaffold" as Body text (14px, secondary color)
- StatusBadge for "Jira Server mock (:8080)" — green dot when responding, red dot when unreachable
- StatusBadge for "Jira Cloud mock (:8081)" — same states
- StatusBadge for "Keychain" — green dot when OS keychain responds to a ping, red dot on failure
- No primary CTA — this is a status view, not an action view

**States:**
- Loading: all badges show gray "Checking..." label
- All healthy: all badges green, no action required
- Partial failure: affected badge(s) show red with specific label ("Port 8080 unreachable", "Keychain unavailable")

## Interaction Contract

Phase 1 has no interactive user workflows. The only interactions are:

| Interaction | Behavior |
|-------------|----------|
| Status badge poll | Auto-polls on mount: `invoke('ping_mock_servers')` and `invoke('ping_keychain')`. No manual refresh button. |
| Error boundary trigger | Renders fallback UI with "Something went wrong" copy. No retry button in Phase 1. |
| Window resize | AppShell is fluid — panel centers correctly at any window size above 320px wide. |

## Accessibility Baseline

These minimums apply to all Phase 1 UI and carry forward to all phases:

| Requirement | Specification |
|-------------|--------------|
| Color contrast | All text meets WCAG AA: 4.5:1 for body, 3:1 for large text (20px+) |
| Focus visible | `outline: 2px solid #3b82f6; outline-offset: 2px` on all focusable elements |
| Motion | No animations in Phase 1. When animations are added in later phases: respect `prefers-reduced-motion`. |
| ARIA | StatusBadge uses `role="status"` and `aria-live="polite"` for polling updates |
