# Phase 37 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** Accessibility hardening only. No new screens, no new visible elements, no new colors, sizes or tokens. Deliverables with a UI surface: (1) one visually hidden app-level polite live region, (2) localized announcement strings, (3) keyboard/focus audit-and-fix of Phase 36 buttons, (4) the WebView2 manual checklist (`37-HUMAN-UAT.md`). The consistency invariant (RQA-01) is a Vitest test with no UI contract.

Sources: 37-CONTEXT.md D-01..D-09 (locked), 36-UI-SPEC.md (tokens, focus table, copy), 35-UI-SPEC.md (toast), `triageActions.ts`, `App.tsx`. Items marked (default) were delegated to Claude's discretion and chosen here.

## Interaction Contract

### Live region (D-03, D-05 default)

| Property | Contract |
|----------|----------|
| Element | One `<div role="status" aria-live="polite" aria-atomic="true" className="sr-only">` (Tailwind `sr-only`; never `display:none` or `hidden`, which suppresses announcements) |
| Component | New `LiveAnnouncer` component (e.g. `src/components/LiveAnnouncer.tsx`) plus a tiny module `announce(message: string)` API that triageActions.ts calls. State lives in a module-level store (Zustand slice `{ message, nonce }`). Selectors must not return `?? []`; use `null`/`''` fallbacks |
| Mount | Mounted once per `App.tsx` render branch, beside each `<Toaster />` (Toaster is rendered in 5 branches at ~L211, 235, 248, 274, 319). Triage actions only occur in the main-app branch, but mount in every branch so the region exists before first use (live regions must be in the DOM before content changes) |
| Repeat messages | Same text twice in a row must re-announce: clear the node text, then set the new text on the next frame (or alternate a trailing zero-width-free toggle via `nonce`-keyed child). Do not append invisible characters |
| Focus | Never focusable, never moves focus |
| Double-announcement (D-05) | The live region is authoritative. Sonner toasts render their own `aria-live` region, so suppress duplication by announcing only the live-region message and leaving the toast text identical in meaning but not re-announced: set the deny toast `important` off (default polite) and keep toast text as the visual affordance. Verify in the manual checklist that deny/undo is heard once (or at worst a brief repeat); if Narrator/NVDA double-speaks, add `aria-hidden` handling to the toast via sonner `toastOptions`/`unstyled` wrapper rather than dropping the live region |
| Error toasts | Existing `toast.error` paths (`denyFailed`, `undoFailed`, `linkFailed`, `restoreFailed`, `handleFailed`) are also pushed through `announce()` so failures are not toast-only |

### Announcement triggers (single writer: `triageActions.ts`)

| Event | Fires when | Message key |
|-------|-----------|-------------|
| Deny | `denyTicket` returns ok (with or without remembered key) | `a11y.denied` |
| Undo | `undoDeny` relink succeeds | `a11y.undone` |
| Undo failed | `undoDeny` fails | existing `triage.undoFailed` text |
| Link / relink | `linkTicket` returns `relinked` (no toast today; announcement is the only non-visual feedback besides the Linked badge) | `a11y.linked` |
| Restore (to seen) | `restoreTicket` ok | `a11y.restored` |
| Handled | `markHandled` ok | `a11y.handled` |
| Link `needs-copy` | not announced here (copy preview dialog owns focus and its own semantics) | - |

Announcements fire after the store write, never before, so what is announced matches the rendered list.

### Keyboard and focus audit (D-06, D-07)

Audit surfaces: `TicketDetailPage`, `TicketDetailPanel`, ticket detail opened from `GroupViewPage`. Pass criteria, fix any failure with the existing button/focus classes:

| Check | Pass criterion |
|-------|---------------|
| Reachability | Deny, Link / "Restore link to KEY", Restore are native `<button type="button">`, reachable by Tab in visual left-to-right order; no `tabIndex={-1}` on them; none inside an `aria-hidden` subtree |
| Operability | Enter and Space both activate each button; no `onClick` on non-button elements |
| Visible focus | Each button shows a visible focus ring on `:focus-visible` (verified in light theme against #f7f7f8 and #ffffff) |
| Accessible name | Visible label equals the accessible name; tooltips stay `aria-hidden` and supplementary; no name relies on the tooltip |
| In-flight | Clicked button is `disabled` while in flight; disabled state must not drop focus to `<body>` (if it does, use `aria-disabled` plus guarded handler for that button) |
| Focus after action | Phase 36 table verified, not redesigned: after Deny, focus on "Restore link to KEY" (or Copy when never linked); after Link, on the Linked badge (`tabIndex={-1}`); after Restore, on Dismiss (panel fallback: close button). Never `<body>` |
| Panel | Panel close button still focused on load; Tab stays reasonable (no trap bug); Escape behavior unchanged |
| Group view | Same detail, same results; Not mine row Restore button reachable by Tab |
| Undo (D-07, verify and document only) | Sonner hotkey (`alt+T`) and Tab reach the toast Undo action within 8 s; after expiry, the Not mine Link/Restore buttons are the keyboard path back. No new shortcut, no extended toast duration |

Heading and landmark changes: none.

### Constraints (project feedback)

No drag and drop; no hover-revealed controls; one entry point per action; no Jira call on Deny; Zustand selectors must not return `?? []`.

## Copywriting Contract

All strings in both `src/i18n/locales/en.json` and `sk.json`, parity-checked by the i18n guard tests (add new keys to expected-key parity). Slovak uses "tiket", never "úloha". Strings include the ticket key and the outcome (D-04). Terminology follows existing tab labels: EN tab "Dismissed" (`nav.notMine`), "Already Linked" (`nav.linked`); SK "Zamietnuté", "Už prelinkované". Build strings with `t('nav.notMine')` interpolation only if the planner wants zero drift; literals below are the default.

| Element | Key | EN | SK |
|---------|-----|----|----|
| Deny announced | `a11y.denied` | {{key}} moved to Dismissed. | Tiket {{key}} bol presunutý do Zamietnuté. |
| Undo announced | `a11y.undone` | Undo: {{key}} restored to Linked {{cloudKey}}. | Späť: tiket {{key}} bol obnovený ako prepojený s {{cloudKey}}. |
| Link announced | `a11y.linked` | {{key}} linked to {{cloudKey}}. | Tiket {{key}} bol prepojený s {{cloudKey}}. |
| Restore announced | `a11y.restored` | {{key}} restored. | Tiket {{key}} bol obnovený. |
| Handled announced | `a11y.handled` | {{key}} marked as handled. | Tiket {{key}} bol označený ako vybavený. |
| Failures | reuse | `triage.denyFailed`, `triage.undoFailed`, `triage.linkFailed`, `ignored.restoreFailed`, `triage.handleFailed` | existing |
| Primary CTA | - | none new (existing: "Restore link to {{key}}" / "Copy to {project}") | existing |
| Empty state | - | not applicable (no new screens) | - |
| Error state | - | reuse existing toasts; each is also announced via the live region | - |
| Destructive confirmation | - | none: Deny is undoable via toast and Restore | - |

Notes: `a11y.undone` and `a11y.linked` need the Cloud key returned by `relink_ticket` (already available in `undoDeny`/`linkTicket`). SK "vybavený" must match the existing handled term in `sk.json`; the planner should reuse that wording. `a11y.denied` should read the existing tab label (`nav.notMine`) via interpolation if the label differs from the literal above.

## WebView2 Manual Checklist Contract (`37-HUMAN-UAT.md`, D-08, D-09)

Single file, run by the user on Windows/WebView2 with Narrator and NVDA, in EN and SK. Each item is a checkbox with expected result and a pass/fail line. Required sections:

1. Folded-in Phase 36 items (the 2 pending in `36-HUMAN-UAT.md`); mark `36-HUMAN-UAT.md` superseded/closed by this file.
2. Focus after deny / link / restore, on the detail page and in the panel (matches the Phase 36 focus table).
3. Keyboard-only run: Tab order, Enter/Space on Deny, Link, Restore in page, panel, group view.
4. Undo toast: reachable by sonner hotkey and Tab within 8 s; after expiry, recovery via Not mine buttons.
5. Live-region announcements for deny, undo, link/relink, restore, handled; confirm once-only speech (D-05) and key + outcome present; link-restore (no toast) is announced.
6. Slovak run of 3 to 5: strings say "tiket", read naturally.
7. Visible focus ring on every checked control.

No consistency steps in the checklist (RQA-01 is automated, D-01).
