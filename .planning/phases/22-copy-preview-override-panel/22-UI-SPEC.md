## Spacing Scale

Declared values (multiples of 4 — matches Tailwind v4 defaults used project-wide):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline padding (`px-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `mb-2`, `px-2 py-1`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`) |
| lg | 24px | Section padding (`px-6`, `mb-6`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used in modal context) |

Exceptions:

- Field label bottom margin: 2px (`mb-0.5`) — matches existing `SourceFieldRow` pattern in `CopyPreviewModal.tsx`
- Field row bottom margin: 12px (`mb-3`) — matches existing modal field rows
- Modal dialog padding: 0 on `DialogContent`, px-6 on header/footer — matches existing `CopyPreviewModal` container pattern
- VirtualizedCombobox trigger min-height: 36px (`min-h-9`) — Phase 21 compactness wrapper pattern (`[&_button]:min-h-9`)
- Touch-target minimum: 44px height for all interactive controls per WCAG 2.5.5 — applies to Copy button and gap fill inputs

Source: existing `CopyPreviewModal.tsx` class patterns + `22-CONTEXT.md`

## Interaction Contract

### Right Column Layout (top to bottom)

```
Target
──────────────────────────────────────────
[Issue Type chooser — VirtualizedCombobox]  ← top of right column
  └─ "Defaulted — no match for 'Bug'"       ← muted caption, 12px, appears only when defaulted

Summary *                                   ← required field indicator via asterisk
[pre-filled from source, always editable]

⚠ Required fields with no mapping           ← amber section, amber-500 border-l-2
  Components *  [fill-in control ▾]  Map →
  Environment * [fill-in control  ]  Map →

─────────────────────────────────────────
[DynamicTargetForm — mapped fields in createmeta order]
  [Assignee picker (UserPickerRenderer — always visible)]
    └─ ✓ milan@example.com pre-filled       ← emerald check if email match found
  [Priority ▾]
  [Labels ▾]
  ...
```

### Issue-Type Chooser

- Component: `VirtualizedCombobox` with `IssueTypeRef` items
- Default selection: case-insensitive name match against source issue type; fallback to first item in list
- Defaulted notice: `text-xs text-brand-muted block mt-1` caption below chooser; hidden once user picks manually
- On change: triggers `loadSchema('target', projectKey, issueTypeId)` + recalculates gaps; shows `Loader2` spinner inline in chooser trigger during load
- Wrapper: `[&_button]:min-h-9` compactness class (Phase 21 pattern)
- Data source: `schemaCacheStore.prewarmedIssueTypes[targetProjectKey]`; on-demand invoke of `pre_warm_target_issue_types` if cache empty

### Summary Input

- Always visible, always editable
- Positioned between issue-type chooser and gaps section
- Input: `w-full bg-brand-surface border border-brand-border rounded px-2 py-1 text-sm focus-visible:ring-2 focus-visible:ring-brand`
- Label: `"Summary *"` (asterisk indicates required; uses `fieldRenderer.required` i18n key pattern)
- Pre-fills from `sourceTicket.fields.summary`

### Gaps Section

- Appears only when `resolvedTargetFields` contains required fields not covered by saved mapping
- Section container: `rounded border-l-2 border-amber-500 bg-amber-500/5 p-3 mb-4`
- Header row: `flex items-center gap-1.5 mb-2`
  - Icon: `AlertTriangle className="w-3.5 h-3.5 text-amber-500"` (`aria-hidden="true"`)
  - Text: `"Required fields with no mapping"` at `text-[13px] font-medium text-amber-700 dark:text-amber-400`
- Each gap row: `flex items-center gap-2 py-1.5`
  - Field name + `*` asterisk: `text-sm text-brand-text`
  - Fill-in control: typed per `FieldSchema` using renderer registry (same as `DynamicTargetForm`)
  - "Map →" link: `Button variant="ghost" size="sm"` with `ExternalLink` icon (w-3 h-3); clicking closes modal, navigates to Settings > Field Mapping
- Empty (no gaps): section is not rendered at all

### Person Picker (PERS-01 through PERS-04)

- Rendered by `UserPickerRenderer` / `MultiUserPickerRenderer` for every `user` / `array[user]` field
- Always visible — even when email match found (PERS-01)
- Email match pre-fill: picker shows matched user as selected value; a `CheckCircle2 className="w-3.5 h-3.5 text-emerald-400"` icon appears inline in the picker trigger (PERS-02)
- No pre-fill, no error when source has no `emailAddress` (PERS-04) — picker renders empty and interactive
- Search: wired through `DynamicTargetForm`'s `searchCallbacks.onSearchUsers` → `search_jira_users_by_domain` (Phase 16 command)

### Copy Button Gating (OVRD-04)

- Button: `Button` component, `variant="default"` (brand-colored)
- Disabled state: when any required target field (from `resolvedTargetFields` where `required === true`) has no value in `overrideValues`
- Disabled tooltip: wraps button in `Tooltip`; `TooltipContent` text: `"Fill in required fields: {field1}, {field2}"` (comma-separated field names)
- Tooltip is only rendered when button is disabled (do not render tooltip on enabled state)
- Copy button label: `"Copy to {{name}}"` — reuses existing `copy.preview.confirm` i18n key

### Loading State (schema refresh on issue-type change)

- `Loader2 className="w-3.5 h-3.5 animate-spin"` appears inline inside the issue-type chooser trigger button (replacing the `ChevronDown` icon) during schema loading
- DynamicTargetForm shows `opacity-50 pointer-events-none` during schema loading to prevent interaction with stale fields
- Loading duration is typically <500ms (local cache hit); on-demand fetch may take 1-3 seconds

### Per-Copy Override Behavior

- Override values stored in `copyStore.overrideValues: Record<string, unknown>` — in-memory only
- No "Save" button — values are ephemeral until copy confirmed
- `copyStore.reset()` clears all override state (OVRD-06) — fires on modal close
- DynamicTargetForm `onChange` writes to `setOverrideValue(fieldId, value)` in copyStore

## Interaction States

### CopyPreviewModal Right Column — State Machine

| State | Trigger | Visual |
|-------|---------|--------|
| `loading_preview` | `startPreview` called | Existing skeleton / loading overlay (no change) |
| `previewing` (initial) | `fetch_cloud_meta` resolved | Issue-type chooser shows (pre-selected), summary editable, gaps section evaluated |
| `issue_type_changing` | User selects new issue type | Chooser trigger shows spinner; DynamicTargetForm opacity-50 |
| `previewing` (gap exists) | Schema loaded, required fields unmet | Amber gaps section visible; Copy button disabled |
| `previewing` (no gaps) | All required fields have values | Gaps section hidden; Copy button enabled |
| `copying` | `confirmCopy` called | Existing progress bar; entire form opacity-50 pointer-events-none |
| `result` | Copy complete | CopyResultModal takes over (no change) |

### Gap Row Fill-In Controls

- Text/URL field: plain `<input type="text">` styled `w-full bg-brand-surface border border-brand-border rounded px-2 py-1 text-sm focus-visible:ring-2 focus-visible:ring-brand`
- Select/multi-select: `VirtualizedCombobox` with `[&_button]:min-h-9` wrapper
- Date: `<input type="date">` same styling as text
- Number: `<input type="number">` same styling as text
- User/multi-user: `UserPickerRenderer` / `MultiUserPickerRenderer`

## Accessibility Contract

- Issue-type chooser: `aria-label="Target issue type"` on VirtualizedCombobox
- Summary input: associated `<label htmlFor="copy-target-summary">` (existing pattern)
- Gaps section: `role="region" aria-label="Required fields with no mapping"` on container
- Gap fill-in controls: each has an associated `<label>` with field name
- Copy button tooltip: `role="tooltip"` on `TooltipContent`; button has `aria-describedby` pointing to tooltip when disabled
- Loading state: `aria-busy="true"` on DynamicTargetForm wrapper during schema refresh
- Person picker pre-fill: `aria-label="{{fieldName}} — pre-filled from source email match"` on picker trigger when green-check state active
- All icons: `aria-hidden="true"` (decorative)
- `AlertTriangle` in gaps header: `aria-hidden="true"` — text label provides the meaning
- Gaps section: `role="alert"` when it first appears (required fields not yet filled) so screen readers announce the problem
