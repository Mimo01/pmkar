<objective>
Close the last Phase 33 gap (SC2, GQA-02, WCAG 2.4.7; 33-VERIFICATION.md gap 1 and 33-REVIEW.md WR-01). When a focused overflow arrow disappears at a scroll end, `updateOverflow` currently moves focus to the active tab with `preventScroll: true`. If the active tab is scrolled out of view, focus lands on an element the user cannot see. The next Tab press then scrolls the strip back.

The fix: send focus to the opposite arrow, which is visible and has just appeared. Fall back to the active tab only when the strip no longer overflows, because then every tab is visible. Add jsdom tests whose rect and scroll mocks make the assertions meaningful. Fix the IN-04 cleanup leak in the tests this plan touches.

Purpose: keyboard users of an overflowing tab strip (about 25 groups, D-09/D-11) always see where focus is.
Output: an updated GroupTabStrip.tsx, rewritten handoff tests, and an amended UI-SPEC scroll-arrow rule.
</objective>
