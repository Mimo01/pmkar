## Layout Contract

### Mapping Grid — Column Structure

The existing grid is `grid-cols-[35fr_35fr_20fr_10fr]`. Static rows extend this same grid with a modified 4-column layout:

```
[Source col 35fr] [Target col 35fr] [Value col 20fr] [Delete col 10fr]
  "Static" badge    Target combobox   Smart value widget  X button
```

The transformer column (col 3, currently 20fr) is **repurposed as the value column** for static rows. The column header label must remain "Transformer" for source→target rows. Static rows show the value widget there instead. This avoids adding a 5th column and keeps the table scannable.

Note: The column headers in `FieldMappingSection` show "Source / Target / Transformer / (delete)" for all rows. Static rows do not have a transformer — the value widget occupies the transformer slot. No column header change needed; the visual distinction comes from the "Static" badge in col 1.

### Static Row Visual Structure

```
┌─────────────────────┬─────────────────────┬──────────────────┬───┐
│ [Static] badge       │ Target combobox      │ Value widget      │ X │
│ 11px text, red tint  │ (same as normal row) │ (smart per type)  │   │
└─────────────────────┴─────────────────────┴──────────────────┴───┘
```

- Col 1 (source): `<span>` with "Static" badge — `inline-flex items-center px-1.5 py-0.5 rounded text-[11px] font-medium text-brand bg-brand/10 border border-brand/30`
- Col 2 (target): `VirtualizedCombobox` — identical to normal MappingRow target combobox
- Col 3 (value): smart widget — see "Smart Value Widget" section below
- Col 4 (delete): `<button>` — identical to normal MappingRow delete button (`h-9 w-9 rounded hover:bg-brand-surface-hover text-brand-muted hover:text-destructive`)

### Pending Static Row (before target is selected)

When "Add static value" is clicked, insert a new static row with:
- Col 1: "Static" badge (same styling as above)
- Col 2: Target combobox — opens immediately (placeholder: "Pick a target field")
- Col 3: Empty / dimmed placeholder text "—" until target is selected (same as normal pending row)
- Col 4: X cancel button

Once a target is selected, col 3 renders the appropriate smart value widget immediately (no page reload, no separate step).

### "Add static value" Button

Placed **below** the existing "Add field mapping" button. Both buttons are `ghost` variant, `sm` size, `w-full justify-start`. Vertical order:

1. "Add field mapping" (existing, for source→target rows)
2. "Add static value" (new, for static rows)

Both share `mt-3` top margin on the first button; second button has no extra top margin (they sit adjacent as a button group).

## Smart Value Widget

The value widget in col 3 of a static row adapts to the **target field's schema type**:

| Target field type | Widget | Notes |
|------------------|--------|-------|
| `string`, `number`, `date`, `datetime` | `<input type="text">` styled as shadcn `Input` (`h-9 w-full rounded-md border border-input bg-background px-3 py-1 text-sm`) | Date/datetime: accept ISO string; no date-picker in Phase 27 |
| `option` (SingleSelect) | `VirtualizedCombobox` loaded with `allowed_values` from schema cache | Displays option name; stores option id |
| `option-with-child` | `VirtualizedCombobox` loaded with parent `allowed_values` | Child value selection deferred (Phase 27 stores parent only) |
| `array` of `option` (MultiSelect) | `VirtualizedCombobox` with multi-select mode if supported, else comma-separated text input | See note below |
| `array` of `string` (Labels) | `<input type="text">` — comma-separated; hint text "Separate labels with commas" below input | Pipeline splits on comma and trims |
| User fields, Priority | Not rendered — these target types excluded from static mapping | If surfaced, widget shows a disabled `<input>` with placeholder "Not supported in this phase" |

**Multi-select note:** `VirtualizedCombobox` is not currently multi-select. For MultiSelect (array of option) fields in Phase 27, use a comma-separated text input identical to the Labels widget (input type=text with placeholder "Separate values with commas"). Add a tooltip explaining the format. This avoids scope creep while remaining functional.

**Widget sizing:** All value widgets use `min-h-[36px]` (`h-9` where applicable) matching the combobox triggers in the other columns.

## Interaction States

### Auto-save pattern (matches existing MappingRow)

Static row value changes use the identical auto-save pattern as `MappingRow`:
1. User changes value in the widget
2. `invoke('set_field_mapping', { row: updatedRow })` fires immediately on change/blur
3. Green `Check` + "Saved" text flashes in col 4 for 1500ms
4. On error: `toast.error(t('settings.fieldMapping.saveError'))`

### Delete static row

Identical to normal row delete:
- `invoke('delete_field_mapping', { sourceFieldId: '__static__{targetFieldId}' })`
- Row removed from list immediately on success
- On error: `toast.error(t('settings.fieldMapping.deleteError'))`
- No confirmation dialog. Static rows have no downstream data risk; deletion is immediately reversible by re-adding.

### Drift detection (no change)

Static rows cannot drift (they have no source field to go missing). The `driftedSourceFieldIds` set will never match a `__static__` sentinel because the drift check compares target field IDs against the target schema, not source field IDs. No special handling needed.

## Accessibility Contract

- "Static" badge: `aria-label="Static mapping — no source field"` on the badge `<span>`. Tooltip content is supplementary.
- "Add static value" button: `aria-label="Add static value mapping"` (full phrase, not just icon).
- Value widget — text input: `aria-label="{targetFieldName} static value"` derived from selected target field name.
- Value widget — combobox: `ariaLabel="{targetFieldName} static value"` prop passed to `VirtualizedCombobox`.
- Delete button on static row: `aria-label="Delete static mapping for {targetFieldName}"`.
- Saved flash: `aria-live="polite"` (inherits from existing MappingRow pattern).
- All interactive controls reachable by Tab in document order: "Add static value" button, then each static row's target combobox → value widget → delete button.
