3. Add a new Tauri command `check_ticket_changes` that takes the snapshot_db state and calls `check_for_changes`:
```rust
#[tauri::command]
pub fn check_ticket_changes(
    snapshot_db: tauri::State<'_, Arc<Mutex<SnapshotDb>>>,
    ticket_key: String,
    response_json: String,
) -> Result<Vec<FieldChange>, AppError> {
    let db = snapshot_db
        .lock()
        .map_err(|_| AppError::Internal("Snapshot DB lock poisoned".into()))?;
    // POLL-06: This command is ONLY called by the frontend after a successful
    // ticket detail fetch. If the HTTP call failed, this command is never invoked,
    // so last_checked_at is never advanced for failed fetches.
    crate::snapshot_db::check_for_changes(&db, &ticket_key, &response_json)
}
```

4. Add a `get_poll_watermark` Tauri command:

```rust
#[tauri::command]
pub fn get_poll_watermark(

    let db = snapshot_db
        .lock()
        .map_err(|_| AppError::Internal("Snapshot DB lock poisoned".into()))?;

}
```

5. Register `commands::get_poll_watermark` in the `invoke_handler` macro in main.rs as well.

**Design note (per D-10, research Pattern 4):** The watermark-only-on-success guarantee is enforced by the caller structure: the frontend calls `check_ticket_changes` only after `fetch_ticket_detail` succeeds. The SnapshotDb API itself always updates `last_checked_at` when `store_snapshot` is called. The safety comes from the call site, not the data layer.
