## Current Test

[awaiting human testing]

Environment: Windows build (WebView2), Narrator and NVDA, light and dark themes. Review at milestone end.

## Tests

### 1. Search visible on every post-setup screen
steps: Open New, Dismissed, Linked, Watched, a group view, a ticket detail, Settings and the audit log. Then start from a fresh profile with the setup wizard.
expected: The header search field is visible on every post-setup screen and absent in the setup wizard.
result: [pending]

### 2. Ctrl+K focuses search
steps: Press Ctrl+K from the list, from another text input (the per-tab filter) and from a ticket detail. Repeat while the Update/About dialog and a confirm dialog are open.
expected: Search focuses in the first three cases. Nothing happens while a dialog is open.
result: [pending]

### 3. Ctrl+F and the native find bar
steps: Press Ctrl+F on the list and on detail.
expected: The search field focuses and the native WebView2 find bar does NOT open (D-03, best-effort). If the find bar opens, record the issue and log a follow-up to drop Ctrl+F.
result: [pending]

### 4. Shortcut hint and clear button
steps: Look at the empty search field, then type text.
expected: The hint reads "Ctrl K" on Windows. The clear button replaces the hint when there is text.
result: [pending]

### 5. Keyboard navigation and Back
steps: Type a query, use arrow keys, press Enter on a hit, then press Back in the detail and refocus search.
expected: Arrow keys scroll the active option into view. Enter opens the detail. Back returns to the original tab, and refocusing shows the same query and results.
result: [pending]

### 6. Escape behavior
steps: With the dropdown open press Esc once, then again. Repeat on the ticket detail page.
expected: Esc once closes the dropdown, twice clears the query. On the detail page, Esc in the open dropdown does not go Back.
result: [pending]

### 7. Screen reader
steps: Use Narrator and NVDA with the search field and results.
expected: The combobox name, the active option and the polite result count are read. The count is not announced on every keystroke.
result: [pending]

### 8. Contrast in both themes
steps: Switch between dark and light theme and search for a common word.
expected: The mark highlight and the category badge are legible (AA) and the active row is distinguishable.
result: [pending]

### 9. Slovak copy
steps: Switch the UI to Slovak and use search.
expected: Placeholder reads "Hľadať vo všetkých tiketoch…". Badges, no-results text and footer are Slovak. "tiket" appears and "úloha" never does.
result: [pending]

### 10. Diacritics and IME
steps: Type "prihlasenia" when a ticket contains "prihlásenia". Type with Slovak keyboard dead keys.
expected: The ticket is found. Dead-key input works in the field.
result: [pending]

### 11. Snapshot-only group member
steps: Add a ticket to a group, make it drop out of the current fetch, and search for it.
expected: It is found. Accepted limitation: snapshots taken before this phase have no description until the ticket is fetched again.
result: [pending]

### 12. Description edit still raises change dot
steps: Edit the description of a fetched ticket on the server, then poll or refetch.
expected: The change dot and notification still appear (D-07 revised regression check).
result: [pending]
