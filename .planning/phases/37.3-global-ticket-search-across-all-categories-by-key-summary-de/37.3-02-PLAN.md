<objective>
Build the pure, fully unit-tested search engine: shared contracts, diacritic folding with index maps, wiki-markup stripping, and `searchTickets` (match, rank, slice, snippet).

Purpose: D-05, D-08 (snippet data), D-10, D-13, D-14, D-15, D-16. Every later plan (corpus, row, combobox, per-tab filter) builds on these exports. Pure TS lets the risky logic be tested without the DOM.
Discretion choices recorded here:
- The index is precomputed folded strings per ticket, cached in a `WeakMap` keyed on the ticket object (the same idiom as `ticketOrigins` in ticketStore.ts). Entries rebuild lazily after each fetch replaces the array. There is no inverted index.
- Indexed and snippet description text is capped at 20,000 chars after wiki stripping (RESEARCH A4).
- Snippets are about 80 chars, with about 30 chars of context before the first match.
- An exact match on the linked `copiedKey` ranks 0, the same as an exact key match (plan-phase decision).
Output: four modules plus three test files.
</objective>

Implement searchIndex.ts with a module-level `const indexCache = new WeakMap<JiraTicket, IndexEntry>()`. The non-exported `IndexEntry` holds folded `key`, `summary`, `assignee`, `labels` (joined with ', '), `components` (names joined), `fixVersions` (names joined) and `description`. Description is built as: `typeof === 'string'` guard, then `stripWikiMarkup`, then slice to DESCRIPTION_INDEX_CAP, then foldText. The entry also keeps the plain (unfolded, stripped, capped) display strings for description/labels/components/fixVersions/assignee for snippets, a `haystack` = all folded fields joined with '\u0000', and `updatedMs` (NaN becomes 0). Export a test-only `__indexBuildCount()` getter, or count builds via a module counter, so the cache test can assert reuse.

`searchTickets(items, rawQuery, limit = SEARCH_RESULT_LIMIT)`:
1. If `rawQuery.trim().length < SEARCH_MIN_CHARS`, return `{ hits: [], total: 0, words: [] }`.
2. `words = parseQuery(rawQuery)`.
3. For each item, get or build the entry. Fold `item.copiedKey` per call (it lives on triage state, not on the ticket). The item matches when every word is in `haystack` or in the folded copiedKey (D-13).
4. Rank (D-15, plan-phase decision): 0 when `words.length === 1` and (entry.key === w or foldedCopiedKey === w); 1 when entry.key.startsWith(words[0]); 2 when every word is in entry.key or entry.summary; otherwise 3.
5. Sort by rank asc, then updatedMs desc, then key `localeCompare` asc.
6. `total` = matched count, then slice to `limit`.
7. Only for sliced hits, compute snippet: when some word is not in key or summary, take the first such word and search in field order description, assignee, labels, components, fixVersions, copiedKey. Use the first field whose folded value contains the word. The snippet text is `buildSnippet(display, words)` for description, and the plain joined display value for the other fields (also passed through buildSnippet, so long label lists are trimmed).

`buildSnippet(text, words)`: collapse whitespace, then use foldWithMap to find the earliest occurrence of any word. Let start = max(0, origIndex - 30) and end = min(len, start + SNIPPET_LENGTH). Prefix '…' when start > 0 and suffix '…' when end < len. When no word is found, return the first SNIPPET_LENGTH chars.

Use only `includes`/`indexOf`/`startsWith`, never `new RegExp` on input (T-37.3-04). Put the 1000-ticket fixture builder in the test file (Wave 0 perf helper).
