### WR-01: The Enter flush announces "N results" after the ticket has already opened

**Files modified:** `src/features/search/GlobalSearch.tsx`, `src/features/search/__tests__/GlobalSearch.test.tsx`
**Commit:** 28387ce
**Status:** fixed: requires human verification (this is a state-handling change; check it with a screen reader in WebView2)
**Applied fix:**
- The announce effect now returns early when `!open`. `open` is read inside the effect but is deliberately not a dependency, and the biome-ignore comment says so.
- When the query is still pending, the Enter branch no longer sets `debounced` before it navigates. It sets `debounced` only when it stays in the dropdown: no match, below the minimum length, panel not ready, or the host refused.
- The pending debounce timer still fires after navigation, but the `!open` guard stops it from announcing.
- New test "WR-01 (re-review)": type, press Enter before the debounce, then flush, and assert that the announcer received nothing. The test fails against the old code and passes with the fix.
- The existing tests CR-01a to CR-01e and the announce tests still pass.

### WR-02: `LINK_BARE` and `LINK_WITH_TEXT` are still unbounded and quadratic on unmatched `[`

**Files modified:** `src/features/search/wikiText.ts`, `src/features/search/__tests__/wikiText.test.ts`
**Commit:** 1b46f61
**Applied fix:**
- `LINK_WITH_TEXT` and `LINK_BARE` now limit each span to 1-500 characters on a single line.
- `MACRO_TAGS` parameters are limited to 0-200 characters on a single line.
- Measured in Node:
  - 20,000 × `[`: 33 ms (was 310 ms)
  - `[a|` × 6,666: 10 ms (was 114 ms)
- Added a pathological test for both inputs with a 100 ms bound. I chose 100 ms instead of the suggested 50 ms to leave room for slow CI runners (see IN-09).
- Added a test that link text does not join across lines. Side effect: a link that spans more than one line, or is longer than 500 characters, now keeps its brackets in the snippet.
