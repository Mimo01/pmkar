## Warnings

### WR-01: The Enter flush announces "N results" after the ticket has already opened (regression from the CR-01 fix)

**File:** `src/features/search/GlobalSearch.tsx:145-156, 58-66`
**Issue:** On a pending query, the Enter branch calls `setDebounced(query)` and then navigates and calls `setOpen(false)`. The announce effect depends on `[debounced, ready, total]` and does not check `open`. It therefore fires on the next commit and announces "N results" (or "No results") for a panel that has just closed.

`GlobalSearch` stays mounted across this navigation. The list branch and the detail branch in `App.tsx` (lines 280-300 and 302 onward) both render `ErrorBoundary > NavigationContext.Provider > AppShell`, so React keeps the instance. (This also makes the `searchStore.ts:4-6` comment, "remounts AppShell", inaccurate for the list-to-detail path.) The announcement then overwrites the single LiveAnnouncer region at the moment the detail page appears. A screen-reader user who types a key and presses Enter hears a result count instead of anything about the ticket they opened.

Before the fix, Enter on a settled query never changed `debounced`, so this path did not announce. The fix turned the old IN-02 edge case into something that happens on every fast jump to a key, which is the main flow.
**Fix:** Announce only while the panel is open, and avoid changing `debounced` when navigation succeeds:
```tsx
useEffect(() => {
  if (!announcedOnce.current) { announcedOnce.current = true; return; }
  if (!open || !ready || debounced.trim().length < SEARCH_MIN_CHARS) return;
  announce(total === 0 ? t('search.live.none') : t('search.live.count', { count: total }));
}, [debounced, ready, total]); // open read but intentionally not a trigger

// Enter branch: flush only when we stay in the dropdown
const fresh = searchTickets(items, query).hits[0];
if (fresh && onOpenTicket(fresh.item.ticket.key)) { setOpen(false); setActiveKey(null); return; }
setDebounced(query);
```
Add a test that types, presses Enter without advancing timers, then flushes, and asserts that `useAnnouncerStore` did not receive a count message.

### WR-02: `LINK_BARE` and `LINK_WITH_TEXT` are still unbounded and quadratic on unmatched `[`

**File:** `src/features/search/wikiText.ts:5-6, 15-16`
**Issue:** The 37.3-08 fix bounded only `WRAPPED`. `/\[([^\]]+)\]/g` scans to the end of the input from every `[` that has no closing `]`, and `LINK_WITH_TEXT` does the same from every `[x|`. These are the same problem class as the old WR-03, and the 20k cap only limits how bad it gets. Measured in Node with the current regexes:
- 20,000 × `[`: **310 ms**
- `[a|` × 6,666: **114 ms**

`buildEntry` runs synchronously on the UI thread, and it runs again for that ticket after every poll because the WeakMap is keyed by ticket object. A description like this (a pasted array dump or minified code) therefore stalls the input for about 300 ms after each poll. The header comment, "Constant, bounded regexes only (T-37.3-04)", is still not true. The new pathological test (`wikiText.test.ts`, ` [a` × 6,666, under 1000 ms) passes at about 100 ms, so it does not catch this.
**Fix:** Bound the spans and keep them on one line:
```ts
const LINK_WITH_TEXT = /\[([^\]|\n]{1,500})\|([^\]\n]{1,500})\]/g;
const LINK_BARE = /\[([^\]\n]{1,500})\]/g;
const MACRO_TAGS = /\{(?:code|noformat|quote|panel|color)(?::[^}\n]{0,200})?\}/g;
```
Add a `'['.repeat(20_000)` case to the pathological test with a tight bound (for example under 50 ms).

### IN-06: The new `WRAPPED` boundaries stop unwrapping common markup and still remove leading minus signs (partial regression from the WR-03 fix)

**File:** `src/features/search/wikiText.ts:9`
**Issue:** The new rule needs whitespace or start-of-string before a span, and only `\s $ . , ; : ! ? )` after it. Spans touching other punctuation are now left as-is:
- `(*bold*)` stays `(*bold*)`
- `"*bold*"` stays unchanged
- `*bold*'s` stays unchanged

The stray markers then appear in the description snippet. Matching still works, because the markers do not break substring search.

Separately, `-` is a delimiter, and the lazy span can cross words: `x -1 and y-` becomes `x 1 and y`. That text is also folded into the description haystack, so a query of `-1` will not match that description.
**Fix:** Allow opening punctuation before a span (`(^|[\s(\["'])`) and quotes or brackets after it (`(?=[\s.,;:!?)\]"']|$)`). Consider limiting `-`, `+` and `^` spans to a single word (`[^\s]{1,200}`) so they cannot cross words.

### IN-07: Enter during IME composition triggers navigation

**File:** `src/features/search/GlobalSearch.tsx:144`
**Issue:** The `Enter` case does not check `e.nativeEvent.isComposing`. With an IME active, the Enter that confirms a composition opens a ticket. This is rarely an issue for SK/EN input, but it is a standard combobox guard.
**Fix:** Add `if (e.nativeEvent.isComposing) return;` at the top of `handleKeyDown`.

### IN-08: On a pending query, Enter ignores a row highlighted with the arrow keys

**File:** `src/features/search/GlobalSearch.tsx:109-111, 145-156`
**Issue:** If the user presses an arrow key and then Enter within the 150 ms debounce window, the highlight sits on a row of the stale result, but Enter opens the live `hits[0]`. The code comment acknowledges this, but the ticket opened can differ from the one highlighted.
**Fix:** Optionally ignore Arrow, Home and End while `query !== debounced` (or flush the debounce on them), so the highlight always refers to the live result.

### IN-09: Wall-clock assertions in unit tests may be flaky on slow CI

**File:** `src/features/search/__tests__/searchIndex.test.ts:176, 190-196`, `src/features/search/__tests__/wikiText.test.ts:45-49`
**Issue:** The tests use `performance.now()` thresholds (100 ms and 1000 ms). The 100 ms index-performance assertion is the one most likely to fail under a loaded runner.
**Fix:** Loosen the thresholds or move them to a benchmark suite. Keep the functional assertions (cap respected, output shrinks).
