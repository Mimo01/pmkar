# Phase 37.3 — UI Design Contract

> Visual and interaction contract for the global ticket search (header combobox + results dropdown) and the widened per-tab filter. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: decisions D-01..D-17 from 37.3-CONTEXT.md; tokens from `src/index.css`; patterns from `TicketFilterBar.tsx` and `AppShell.tsx`; user preference memory. Everything is pre-populated from the codebase and context, so no user questions were needed.

| Property | Value |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between icon and text, gap between chips, badge padding-y |
| sm | 8px | Result row padding-y, gap between row parts, input icon inset |
| md | 16px | Result row padding-x, dropdown footer padding-x |
| lg | 24px | Empty-state vertical padding |
| xl | 32px | Header search field height (h-8) |
| 2xl | 48px | not used in this phase |
| 3xl | 64px | not used in this phase |

Layout:
- Header search field: 32px high, `w-[320px]` max `w-full`, centered in the `AppShell` header between the brand mark and the icon buttons (the header is `justify-between`). Under 640px it shrinks to flex-1 with min 160px.
- Dropdown panel: absolutely positioned `top-full mt-1`, same left edge as the field, width `w-[560px]` (max `calc(100vw - 32px)`), `max-h-[480px] overflow-y-auto`, `z-50`, `rounded-md border border-brand-border bg-brand-surface shadow-lg` (matches assignee dropdown).
- Result row: min-height 48px (two lines max when a snippet exists: 64px), `px-4 py-2`, 8px between parts.

Exceptions: existing header and filter bar use 2px/6px/10px Tailwind steps (`gap-0.5`, `py-1.5`, `gap-2.5`). New code in this phase must use only the values above. Existing code is left untouched.

## Typography

Exactly 3 sizes and 2 weights used by this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (summary, input text, empty-state heading, snippet) | 14px (`text-sm`) | 400 regular | 1.5 |
| Label (key, category badge, shortcut hint, footer note, hint line, assignee) | 12px (`text-xs`) | 600 semibold for key and badge; 400 for the rest | 1.5 |
| Heading (no-results heading only) | 16px (`text-base`) | 600 semibold | 1.2 |

Notes:
- Display: not used.
- Match highlight uses weight 600 (no size change) plus a neutral background (see Color). Never change the font size on highlight.
- Summary truncates with ellipsis on one line (`truncate`); the snippet is one line, ellipsis at ends, max about 80 characters of context centered on the first match (planner may tune, discretion).

## Color

Uses existing tokens only. Both themes come from the existing `body.dark` overrides.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-brand-bg` (#f7f7f8 / #161617) | Page background behind the header |
| Secondary (30%) | `bg-brand-surface` (#ffffff / #1e1e20) | Header, dropdown panel, input fill (`bg-brand-surface/50` like the filter bar) |
| Accent (10%) | `--color-brand` #c02232 (dark focus ring #e5484d via `focus-ring`) | See reserved list |
| Destructive | `--color-destructive` | Not used in this phase (no destructive actions) |

Supporting neutrals:
- Active (arrow-key) option and hover: `bg-brand-surface-hover`.
- Match highlight: `bg-brand-surface-raised` background with `text-brand-text`, weight 600, `rounded-sm`, no underline. Not accent, not yellow.
- Secondary text (key, assignee, snippet, hint, footer): `text-brand-text-secondary` (AA on both themes). **Do not use `text-brand-muted` on text** (banned). `brand-muted` is permitted only for the decorative search icon and the clear icon at rest, as in `TicketFilterBar`.
- Category badge: neutral, `border border-brand-border bg-brand-surface-raised text-brand-text-secondary text-xs rounded px-2 py-0.5`. Same neutral style for New, Dismissed, Linked, Watched (no per-category colors, so it cannot be confused with group chips).
- Group chips: existing `GroupChips` component with `group-chip` utility (tinted background and border, neutral text). Rendered without tooltips and without click handlers inside results.
- Do NOT use `brand-accent` (undefined token).

Accent reserved for (exhaustive):
1. Focus ring on the search input (`focus:ring-1 focus:ring-brand`, same as filter inputs).
2. Keyboard focus ring on the clear (X) button.
No other accent use: not for highlight, active option, badges or the shortcut hint.

## Interaction Contract

### Global search field (AppShell header)
- Always visible on every screen including settings and ticket detail. `role="combobox"`, `aria-expanded`, `aria-controls` (listbox id), `aria-autocomplete="list"`, `aria-activedescendant` (active option id), `aria-label` = placeholder string. Wrapped in `role="search"`.
- Left `Search` icon 14px (`w-3.5 h-3.5`, `aria-hidden`). Right side: clear X button (visible only when text is non-empty, 16px hit target extended to 24px, `aria-label` "Clear search"), otherwise the shortcut hint pill.
- Shortcut hint: `Ctrl K` on Windows/Linux, `⌘K` on macOS, 12px, `text-brand-text-secondary`, border `border-brand-border`, `rounded px-1`, `aria-hidden` (the shortcut is conveyed via `aria-keyshortcuts="Control+K Meta+K Control+F Meta+F"` on the input). Hidden while the field has text or focus-with-text.
- Ctrl/Cmd+K and Ctrl/Cmd+F focus the input, select existing text, and `preventDefault`. Ignored while any modal dialog (`role="dialog"` open / `aria-modal`) is open. Not intercepted when focus is in another text input other than focusing search is the only effect (still focuses search, per D-03). No single-key shortcuts.

### Open / close and query behavior
- Dropdown opens when the query has at least 2 characters (after trim), debounced 150 ms. With 0 or 1 character: dropdown closed (no hint panel).
- Esc once: closes dropdown, keeps text. Esc again: clears text. Click outside (mousedown) closes the dropdown without clearing.
- Focusing the field again with a kept query re-opens the dropdown with the same results (D-09).
- Selecting a result (click or Enter): opens `TicketDetailPage`, closes dropdown, keeps query text in the field. Back returns to the originating tab. Focus follows existing detail focus rules (Phase 36).
- Mouse: hover sets the active option; click selects. Rows are `role="option"` inside `role="listbox"`; options are not individually tabbable (focus stays in the input).

### Keyboard
- ArrowDown/ArrowUp moves the active option (wraps at ends), scrolls it into view; Home/End jump while the dropdown is open. Enter opens the active option (first option is NOT auto-active; Enter with no active option and results present opens the first result). Tab closes the dropdown and moves focus on normally.

### Result row (top to bottom, left to right)
- Line 1: `KEY` (12px semibold, `text-brand-text-secondary`, no wrap) · summary (14px, `text-brand-text`, truncate, flex-1) · `PriorityIcon` (16px) · `UserAvatar` (xs size) with assignee name at 12px only when width allows (hide name under 640px).
- Line 1 end: neutral category badge, then `GroupChips` (max visible per existing component rules, overflow as existing).
- Line 2 (only when no match in key or summary): snippet, 12px, `text-brand-text-secondary`, single line with ellipsis, prefixed with a plain field label for non-description fields (e.g. "Labels:", "Assignee:", "Linked key:"; description has no prefix).
- Highlight applies to key, summary and snippet for each query word (diacritic-insensitive; highlight the original characters). Use `<mark>` styled per Color.
- Each ticket appears once. Rows have no action buttons, no hover-revealed icons, no restore or triage controls (feedback: explicit actions, no row restore).

### Footer and states
- Footer line (only when total > 20): "Showing 20 of {n}, refine your search", 12px, `text-brand-text-secondary`, `px-4 py-2`, `border-t border-brand-border`, not an option.
- No results: centered block, `py-6 px-4`: heading (16px semibold) + hint (14px, `text-brand-text-secondary`) listing searched fields. No remote-search button.
- Loading: none (local, synchronous); no spinner or skeleton. If the ticket data has not loaded yet, show the no-results copy only after the first data load; before that show nothing.
- Live region (`LiveAnnouncer`, polite): announce "{n} results" / "No results" after each debounced search, not on every keystroke; do not announce on selection.

### Per-tab filter (TicketFilterBar, D-02)
- Layout, size, and style unchanged. Only strings change: placeholder and `aria-label` become "Filter by key or summary…" / SK equivalent. Matching now key or summary; use the same diacritics-insensitive, all-words rules as the global search for consistency. No highlight in list rows (not in scope).
- Core tabs show no count pills. The global search does not add counts to tabs.

### Responsive/WebView2
- Dropdown width clamps to the viewport. Verified items for the WebView2 checklist: shortcut hint renders per platform, Ctrl+F does not open the browser find bar, Ctrl+K focus, IME input, dark theme contrast of highlight and badge, dropdown scrolling with arrow keys.

### Motion
- Dropdown appears with no animation, or at most a 100 ms opacity transition (`transition-colors duration-100` for rows, matching existing). Respect `prefers-reduced-motion` (no transitions).
