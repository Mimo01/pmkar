## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip padding, inline element separation |
| sm | 8px | Compact element spacing, `space-y-0.5` nav stacking (2px visual; 8px unit) |
| md | 16px | Default element spacing inside section cards, combobox row padding |
| lg | 24px | Section card inner padding (`p-5` = 20px; section content `py-6` = 24px) |
| xl | 32px | Section content horizontal padding (`px-8`) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level empty state vertical centering (`py-16`) |

Exceptions:
- Touch targets for [Accept] / [Dismiss] / [Remove] row actions: minimum 32px height (keyboard accessible, compact density)
- Drift warning badge: 4px padding around icon (xs)
- Sidebar nav item: `px-3 py-1.5` (12px / 6px) — matches existing NavItem pattern exactly

Source: `SettingsPage.tsx` patterns measured directly.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / row label | 14px (text-sm) | 400 (normal) | 1.5 |
| Label / nav item | 13px (text-[13px]) | 400 (normal) / 600 (semibold) when active | 1.5 |
| Section heading | 11px (text-[11px]) | 600 (semibold), uppercase, tracking-wider | 1.2 |
| Group heading | 10px (text-[10px]) | 600 (semibold), uppercase, tracking-widest, muted/70 | 1.2 |

Notes:
- Active nav item uses `font-semibold text-brand-text` (600 weight)
- Inactive nav item uses `font-normal text-brand-muted` (400 weight)
- "Last refreshed Xm ago" timestamp: `text-[13px]` weight 400, `text-muted-foreground` — collapsed into the 13px size; the muted color distinguishes it visually without a separate size
- Drift warning text: 13px (text-[13px]), weight 400 (normal), amber/orange color — the amber color provides sufficient visual differentiation; a third weight is not needed

Source: `SettingsPage.tsx:232–241`, `553–568` measured directly.

## Interaction Contract

### Auto-save feedback

Every mutation (combobox change, Accept suggestion, Delete row) triggers an immediate Tauri invoke. Feedback:
- Success: a `✓` check mark (`Check w-3.5 h-3.5 text-green-600`) appears inline adjacent to the changed row for 1500ms, then fades
- Error: a `toast` (shadcn Sonner) with `variant="destructive"` — "Failed to save mapping. Try again."
- No global "Save" button exists

### Combobox behavior

Target field combobox:
- Placeholder: "Select target field"
- Searchable — type to filter
- Uses `VirtualizedCombobox` from Phase 20 (cmdk + `@tanstack/react-virtual`)
- Items: `{ label: field.name, value: field.field_id }` from `field_schema_cache` target side
- Each item shows field name + field type chip in muted text (e.g., "labels  string")

Transformer combobox:
- Placeholder: "Select transformer"
- Items filtered by target field type (see transformer filtering rule below)
- Not virtualized (≤ 8 transformer options max)

Transformer filtering rule:
- `string` / `text` / `url` type → `identity`, `wiki_to_adf`
- `user` / `array<user>` type → `user`, `identity`
- `priority` type → `priority`, `identity`
- `array<string>` (labels/components/versions) → `identity`
- `number` / `date` / `datetime` → `identity`
- All types → always include `identity` as fallback
- Invalid combos are excluded from the list (not just disabled)

### Schema refresh

1. User clicks "Refresh schema" button
2. Button shows `Loader2 animate-spin`, disabled
3. `refresh_field_schema_cache` Tauri command called
4. On success: "Last refreshed" timestamp updates to "just now"; suggestions panel and drift warnings re-evaluate
5. On error: toast "Schema refresh failed. Check your connection and try again."
6. Button returns to idle state

### Dismissed suggestions persistence

Dismissed suggestions are stored as mapping rows with `target_field_id = ""` (empty string sentinel) in `field_mapping` table. This uses the existing `set_field_mapping` command — no new storage needed. On re-evaluation after refresh, source fields with a row having empty `target_field_id` are treated as explicitly dismissed and not re-surfaced.

### Load sequence

On `FieldMappingSection` mount:
1. `get_field_mapping` → all saved rows
2. `get_cached_schemas("target", projectKey, issueTypeId)` → target field list
3. Cross-reference rows against cache → identify drifted rows
4. Cross-reference cache against rows → identify unmapped source fields → compute suggestions
5. Render table + suggestions panel

Show a `Skeleton` (shadcn) for 3 rows while loading; no blank flash.

Destructive actions in this phase:
- Delete mapping row: no confirmation dialog (low-risk; auto-save means undo requires re-adding). Show `X` icon button only, with accessible `aria-label`.
- Dismiss suggestion: no confirmation. Reversible by doing a schema refresh (dismissed rows re-appear only if explicitly added back).
- Drift [Remove]: no confirmation. Same rationale — row already invalid.

## Accessibility Contract

- All comboboxes: `aria-label="{source field name} target field"` and `aria-label="{source field name} transformer"`
- Delete button: `aria-label="Remove mapping for {source field name}"`
- Drift warning: `role="alert"` on the warning container per row
- Suggestions panel toggle: `aria-expanded` on collapsible trigger
- Auto-save success indicator: `aria-live="polite"` region so screen readers announce "Saved"
- Refresh button: `aria-busy="true"` when in loading state
- "Last refreshed" timestamp: `aria-label="Last refreshed {relative time}"` for screen readers
- All interactive elements: `focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2`
- WCAG AA contrast required on drift amber text: amber-600 (#d97706) on white = 3.8:1 — use amber-700 (#b45309) in light mode for 4.6:1 compliance; amber-400 (#fbbf24) in dark mode on `#1e1e20` = 7.2:1 OK
