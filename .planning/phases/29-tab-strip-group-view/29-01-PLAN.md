<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI input -> Rust create/rename | Group names typed by the user cross into the authoritative Rust validator and SQLite |
| Rust IPC -> Zustand store | list_groups / list_group_memberships payloads populate UI state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Spoofing | validate_group_name / validateGroupName | mitigate | Strip U+200B..U+200F, U+2060..U+2064, U+00AD, U+FEFF from the comparison key and reject empty keys on both sides, so a visually identical "Team\u200B" cannot impersonate "Team" |
| T-29-02 | Tampering | groupStore.hydrate | mitigate | Generation counter drops stale responses; memberships whose groupId is not in the same response's groups are discarded |
| T-29-03 | Denial of Service | groupStore.hydrate catch | mitigate | Keep last good state and set hydrateError instead of wiping groups, so one IPC failure cannot blank the tab strip |
| T-29-04 | Information Disclosure | hydrate failure after scope switch | accept | Last good state may briefly belong to the previous scope until the next successful hydrate; same local user, no cross-user data |
</threat_model>
