<objective>
Close the single UAT gap from Phase 30 (Test 1): in light theme, the teal, green, orange and pink group colors render transparent.

Root cause (from .planning/debug/group-colors-not-rendering.md): the light palette is declared inside Tailwind v4 `@theme {}` in src/index.css. Tailwind v4 only emits `@theme` variables whose names appear literally in scanned sources, but `groupColorVar` in src/features/groups/colors.ts builds `var(--color-group-${token})` at runtime, so the scanner never sees them. Only blue/amber/purple/slate survive, by accident (literal mentions in tests and .planning docs). The dark palette lives in a plain `body.dark` rule and is complete.

Fix: move the 8 light `--color-group-*` declarations out of `@theme` into a plain `:root` rule (same pattern as `body.dark`), so they are always emitted. Update the colors.ts vs index.css parity test to read light values from the new block, add a regression guard, and confirm with a production build that all 8 light variables are in the emitted CSS.

Purpose: every swatch and tab dot visible in both themes, and the palette no longer depends on accidental literal mentions.
Output: updated src/index.css, colors.ts doc comment, colors.test.ts.
</objective>
