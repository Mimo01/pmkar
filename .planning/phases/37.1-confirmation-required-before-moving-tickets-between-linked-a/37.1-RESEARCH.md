## Summary

The vocabulary: Linked = `copied` (with `copiedKey`), Not mine = `ignored` (the Not mine tab also lists `handled`, see `ticketListUtils.ts` lines 29, 39). [VERIFIED: codebase] The only transitions between them are in `src/features/tickets/triageActions.ts` (frontend, single writer) backed by `set_triage_state` / `relink_ticket` (Rust). Today **none of them asks for confirmation**: Deny (Linked to Not mine) fires on button click, and "Restore link to KEY" (Not mine to Linked) fires on click via `relink_ticket`. Both only have an Undo toast (deny) or nothing (relink).

The audit found **no truly automatic Linked/Not mine transition** in the backend: fetch only inserts `new` for unknown keys and deletes done rows with `copied_key IS NULL`; the poll engine only reads notification prefs and writes snapshots, never triage state; `set_triage_state` rejects `copied`. [VERIFIED: commands.rs 797-820, triage_db.rs 485-502, poll_engine.rs grep] There is **one implicit path**: the Undo toast for a deny (`undoDeny`) calls `relink_ticket` whenever the ticket is still `ignored` and `prev.copiedKey` existed, even when the ticket was *not Linked* before the deny (e.g. `seen` with a remembered key after Restore). That would move a non-Linked ticket to Linked without any prior Linked state. Fix this.

The phase is therefore mostly: add a shared confirm step in front of the two user-initiated transitions, tighten Undo, add a guard test that locks the "only confirmed callers" invariant, and add EN/SK strings.

**Primary recommendation:** Add one shared `ConfirmTransitionDialog` (Radix Dialog, `role="alertdialog"`, modeled on `DeleteGroupDialog`) driven from `useTriageDetailActions` so page, panel and group view all get it; call `denyTicket`/`linkTicket` only after confirm; make `undoDeny` restore the prior state (relink only if the prior state was `copied`); add a static guard test that `denyTicket`/`linkTicket`(relink path) are called only from the hook.

## Architecture Patterns

### Flow
```
Button click (Deny | Restore link to KEY)       [page / panel / group-view detail]
   -> useTriageDetailActions.requestDeny / requestLink
        - Deny: always pending-confirm when isLinked
        - Link: pending-confirm only if rememberedKey; else linkTicket directly (opens copy preview)
   -> ConfirmTransitionDialog (alertdialog; Cancel autofocused; Esc/Cancel = no-op, focus returns to trigger)
   -> Confirm -> handleDeny/handleLink (existing code, focus rules unchanged)
        -> triageActions.denyTicket / linkTicket -> invoke set_triage_state | relink_ticket
        -> announce() + Undo toast (deny)
Automatic sources (fetch, poll, hydrate) -> never call the above
```

### Recommended structure
```
src/features/tickets/
  ConfirmTransitionDialog.tsx   # new, presentational; props {kind:'deny'|'link', ticketKey, cloudKey, open, onConfirm, onCancel, busy}
  useTriageDetailActions.ts     # add confirm state: pendingConfirm, requestDeny, requestLink, cancelConfirm; keep handleDeny/handleLink as the confirmed executors
  triageActions.ts              # fix undoDeny prior-state; no confirm logic here
  __tests__/ConfirmTransitionDialog.test.tsx, transitionGuard.test.ts (new)
```

Why the hook, not `triageActions`: `denyTicket` is shared with Dismiss (New to Not mine, no confirm wanted) and `linkTicket` returns `needs-copy` for never-linked tickets. Page, panel and group view already share the hook (Phase 36), so one wiring point covers all three. Keep the dialog mounted at the component level (hook returns state; each of Page/Panel renders `<ConfirmTransitionDialog {...tri.confirm} />`).

### Dialog pattern to copy (`src/features/groups/DeleteGroupDialog.tsx`)
- `Dialog` + `DialogContent role="alertdialog" hideClose`, `onOpenAutoFocus` preventDefault then focus the **Cancel** button (safe default), `onInteractOutside` preventDefault, `onCloseAutoFocus` preventDefault then caller returns focus explicitly.
- Disable both buttons while submitting; ignore double submit with a ref.
- Snapshot the target in a ref so text does not blank during close animation.
- Non-destructive variant for Link (use `default` button variant, not `destructive`); Deny uses default/secondary too (it is reversible), not red.

### Focus interplay with existing hook rules
Existing `pendingFocus` rules (deny to `primary`, link to `badge`, failure to origin) are set inside `handleDeny/handleLink`. Keep them; set them at Confirm time only. On Cancel, return focus to the originating button (`denyRef` for deny, `primaryRef` for link) via `onCloseAutoFocus`. Do not set `pendingFocus` in `requestDeny/requestLink`.

## Common Pitfalls

### Pitfall 1: Undo moves a non-Linked ticket to Linked (existing bug, on the "never automatic" boundary)
`denyTicket` shows the Undo toast when `prev?.copiedKey` is truthy, regardless of `prev.state`. After `restoreTicket` (state `seen`, key kept) then Dismiss, Undo calls `relink_ticket`, producing `copied`. **Fix:** record `prev.state` in the toast closure; Undo restores `seen`/`new` via `applyState` when prior state was not `copied`, and calls `relink_ticket` only when prior state was `copied`. Show the Undo toast only when it will be meaningful (prior state `copied` is the case the string "Linked {{cloudKey}}" describes). Add a test.

### Pitfall 2: Confirm inside `denyTicket`/`linkTicket`
Would also prompt on Dismiss (New to Not mine) and on the needs-copy hand-off, breaking Phase 35/36 tests (`triageActions.test.ts`, `useTriageDetailActions.test.tsx`, keyboard test) that call these directly. Gate at the hook.

### Pitfall 3: Escape closes the detail panel as well as the dialog
`TicketDetailPanel` closes on document `keydown` Escape unless `e.defaultPrevented` (line ~125). Radix calls `preventDefault` on handled Escape in DismissableLayer, so it should be safe, but this is [ASSUMED] from Radix internals; add a test that Esc in the dialog leaves the panel open.

### Pitfall 4: Focus lost after confirm
Dialog unmount plus `onCloseAutoFocus` plus the hook's `pendingFocus` effect can fight. Use `onCloseAutoFocus` preventDefault and let the hook's existing effect (keyed on `state`/`focusTick`) place focus; on Cancel focus the trigger explicitly. The 37 keyboard test (`a11y.triage.keyboard.test.tsx`) must be extended: Deny, then dialog, Enter on Confirm, focus lands on the denied primary.

### Pitfall 5: Link busy/aria-disabled interplay
The Link button uses `aria-disabled` while `linkBusy`. Opening the dialog must not set `linking`; set it only in confirmed `handleLink`. Ignore opening a second dialog while one is pending.

### Pitfall 6: Stale confirmation
Ticket may change underneath (poll, another window) while dialog is open. On confirm, re-check the store entry: Deny requires still `copied`; Link requires still `ignored` with the same `rememberedKey`; otherwise close silently and announce nothing. Also close the dialog when `issueKey` changes.

### Pitfall 7: i18n guards
`noLiteralStrings.test.ts` scans group files and a fixed `EXTRA_FILES` list for literals in toast/announce/aria attrs; `a11yLocale.test.ts` and `detailLocale.test.ts` require SK to contain "tiket" (never "úloh") and equal placeholders EN/SK. Also terminology guards: toasts/announcements must contain the `nav.notMine` label (EN "Dismissed", SK "Zamietnuté") — reuse it in dialog text via `{{tab}}` (the existing `detail.deny.tooltip` does this). Add `ConfirmTransitionDialog.tsx` to `EXTRA_FILES`.

## Code Examples

Hook wiring sketch (names are recommendations):
```typescript
// useTriageDetailActions.ts
const [pending, setPending] = useState<null | 'deny' | 'link'>(null);
const requestDeny = useCallback(() => { if (isLinked) setPending('deny'); }, [isLinked]);
const requestLink = useCallback(() => {
  if (linkingRef.current) return;
  if (rememberedKey) setPending('link'); else void handleLink(); // needs-copy path: preview is the confirmation
}, [rememberedKey, handleLink]);
const confirm = useCallback(async () => {
  const kind = pending; setPending(null);
  if (kind === 'deny' && useTicketStore.getState().triageMap[issueKey]?.state === 'copied') await handleDeny();
  if (kind === 'link' && useTicketStore.getState().triageMap[issueKey]?.state === 'ignored') await handleLink();
}, [pending, issueKey, handleDeny, handleLink]);
```

## Ambiguities for the planner (with recommended defaults)

1. **Does Undo need confirmation?** Default: No. Undo is the explicit reversal, expires after 8 s, user-initiated. Fix Pitfall 1 instead.
2. **Confirm for needs-copy path?** Default: No extra dialog; the copy preview is the confirm. Surface that the copy will move it to Linked only if cheap (optional text).
3. **"Handled" in Not mine tab:** transitions Linked <-> handled are unreachable today. Default: add a test that the handled button is absent for Linked; no dialog.
4. **Restore (Not mine to New, key kept):** not a Linked move. Default: no confirm.
5. **Remember "don't ask again"?** Default: no. The requirement says confirmation required; a skip option undermines it.
6. **Backend enforcement (e.g. `confirmed: true` arg on `set_triage_state`/`relink_ticket`)?** Default: no. The frontend is the only caller, the gate is enforced by the static guard test; adding IPC args churns mocks and Rust tests for no threat reduction (local desktop app). Revisit only if the user wants defence in depth.
7. **Group view row-level actions:** none exist for deny/link, so nothing to change besides inheriting the shared detail.
8. **Wording "Deny" vs "Dismissed":** UI button says Deny, tab says Dismissed/Zamietnuté. Keep existing; do not rename here.
