## Summary

I re-reviewed commits 75985e5, 352d67e, 6719be1 and 873a908. All four original warnings are fixed correctly, and I found no regressions.

- **WR-01:** The confirmed action now runs inside `onResolve`. `onClosed` only returns focus and re-ticks a pending focus request. `submittedRef` stops Radix's `onOpenChange(false)` from re-entering `handleCancel` after a confirm. `confirmTargetRef` is cleared before the action runs, so the re-entrancy guard in `requestDeny` and `requestLink` still holds.
- **WR-02:** The stale guard now notifies. The new `triage.confirm.stale` key exists in both EN and SK, and SK uses "Tiket".
- **WR-03:** The render-phase `setSnapshot` and `setSubmitting` follow React's documented derived-state pattern. It terminates because the guard `target !== snapshot` is false after the update. `useEffect` is the right place to reset the refs, since refs must not be written during render.
- **WR-04:** `e.target.closest` and `confirmOpen` agree. The handler closure is stale only after the render that clears the target, and Radix's `onEscapeKeyDown` `stopPropagation` already shields the same event. The double guard is harmless.

The remaining findings are minor.

## Warnings

### WR-01: Deny stale-guard does not verify the linked key, unlike the link guard

**File:** `src/features/tickets/useTriageDetailActions.ts:163`
**Issue:** The link branch checks both the state and `current.copiedKey !== target.cloudKey`. The deny branch checks only `state !== 'copied'`. If the ticket was re-linked to a different cloud key while the dialog was open (for example by a background sync), the user confirms "Move away from KEY-A" but the deny proceeds against KEY-B. No warning is shown, which is the silent-discard class WR-02 set out to remove, applied in the other direction.
**Fix:**
```ts
if (current?.state !== 'copied' || current.copiedKey !== target.cloudKey) {
  notifyStale(issueKey);
  return;
}
```

## Info

### IN-01: Stale notification fires a toast and a separate live-region announcement with the same text

**File:** `src/features/tickets/useTriageDetailActions.ts:42-46`
**Issue:** Sonner toasts are already exposed in an aria-live region, so screen readers may read the message twice.
**Fix:** Keep one channel, or confirm that `announce` is the established pattern alongside toasts elsewhere in the codebase.

### IN-02: Escape handler can still fire during the dialog exit animation

**File:** `src/features/tickets/TicketDetailPage.tsx:109-121` (same in `TicketDetailPanel.tsx:127-139`)
**Issue:** `confirmOpen` becomes false as soon as `onResolve` clears the target, while Radix keeps the content mounted during its exit animation. A second Escape pressed within that window, with focus outside the `alertdialog`, would navigate back. The window is very small and low impact.
**Fix:** Optional. Defer clearing the guard until `onClosed`, or ignore.
