## Color

All values from `src/index.css` brand token system. Both light and dark modes are supported via CSS variable overrides on `body.dark`.

| Role | Light Value | Dark Value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `#f7f7f8` (`brand-bg`) | `#161617` | Page background, panel background |
| Secondary (30%) | `#ffffff` (`brand-surface`) | `#1e1e20` | Cards, detail panel, tab content areas |
| Accent (10%) | `#c02232` (`brand`) | `#c02232` | Active tab underline border only |
| Destructive | `#dc2626` | `#dc2626` | Error text (no destructive actions in this phase) |

**Change indicator dot color (Claude's Discretion — resolved here):**
Use `#3b82f6` (Tailwind `blue-500`) for the unseen-changes dot. Rationale: blue is universally understood as "unread/new information" (Linear, GitHub, email clients); it does not conflict with the red brand accent or the green copied-state badge. In dark mode, `blue-400` (`#60a5fa`) for sufficient contrast against `#1e1e20` surface.

Accent reserved for:
- Active tab underline border (`border-brand`) in TicketDetailPanel tab bar
- Focus ring on interactive elements (`ring-brand` via `--color-ring`)
- Primary action button background (`bg-brand`) — e.g. "Copy to …" button

The change indicator dot is NOT brand accent color; it uses semantic blue specifically to signal "new information."

Muted text colors:
- `text-brand-muted` (`#8c8c92` light / `#7f7f7f` dark) — old values in diff table, secondary labels
- `text-brand-text-secondary` (`#5c585a` light / `#95959a` dark) — field names, secondary content

## Interaction Contracts

### 1. Change dot indicator (TicketCard)

- **Element:** 6px filled circle rendered as `inline-block` immediately after the ticket key `<span>` in `TicketCard.tsx` (line ~33, inside the `flex items-center gap-2` div)
- **Color:** `bg-blue-500` light / `bg-blue-400` dark
- **Visibility:** Rendered only when `hasUnseenChanges` is true for that ticket key
- **Tooltip:** Wraps dot in `<Tooltip>` from `@/components/ui/tooltip`. Content: "N changes: field1, field2" — e.g. "3 changes: status, priority, comments"
- **Tooltip delay:** 300ms (matches existing `delayDuration={300}` in TicketDetailPanel)
- **Accessibility:** `aria-label="N unseen changes"` on the dot element; tooltip content is `aria-hidden="true"` (screen reader uses aria-label)

### 2. Changes tab (TicketDetailPanel)

- **Tab ID:** `'changes'` — added to the `TabId` union type
- **Tab position:** 6th tab, after "History"
- **Tab label:** `t('detail.tab.changes')` = "Changes"
- **Badge:** `<Badge variant="secondary">` with change count rendered inline after the label text, visible only when `hasUnseenChanges` is true for the open ticket. Example: "Changes 3"
- **Auto-switch:** When `TicketDetailPanel` opens for a ticket with `hasUnseenChanges === true`, set `activeTab` to `'changes'` instead of `'overview'` during the `setActiveTab('overview')` reset in the `useEffect` that fires on `issueKey` change
- **Mark-as-read trigger:** When `activeTab === 'changes'` is set (and the ticket has unseen changes), fire the Tauri command to clear `has_unseen_changes` for that ticket key. Do not fire on other tab activations.

### 3. ChangesTab content — diff table

- **Structure:** Table with 4 columns: Field | Old Value | Arrow | New Value
- **Arrow column:** Contains the Unicode right arrow `→` character (U+2192), `text-brand-muted`, `text-xs`, centered
- **Field column:** Field name in `text-sm font-semibold text-brand-text-secondary` — e.g. "Status", "Priority", "Comments"
- **Old value column:** `text-sm text-brand-muted` — visually de-emphasized
- **New value column:** `text-sm text-brand-text` — normal emphasis
- **Long-text fields:** For `description` field, display "Description changed" in the New Value column (no inline text diff). Old value column shows "—" (em dash). Per D-09.
- **Row divider:** `divide-y divide-brand-border-subtle` on the table body (matches HistoryTab `divide-y divide-brand-border-subtle` pattern)
- **Table wrapper:** `px-5 py-4` outer padding (matches `HistoryTab` `px-5`)
- **Comment/worklog changes:** Rendered as a single row with field "Comments" (e.g. "3 → 5") or "Work Log" — comment count delta, not individual comment content
- **Loading state:** Three skeleton rows matching HistoryTab loading skeleton pattern: `animate-pulse bg-brand-surface-hover rounded h-3`
- **Error state:** `<p className="text-xs text-red-400">{t('detail.changes.error')}</p>` inside `px-5 py-4` wrapper

### 4. Empty state (ChangesTab — no changes detected)

- **Layout:** `flex items-center justify-center py-16` (matches HistoryTab empty state)
- **Text:** `<p className="text-xs text-brand-muted">{t('detail.tab.changes.empty')}</p>`
- **Copy:** "No changes detected since last fetch" (see Copywriting Contract below)

## State Management

Per D-11 and CONTEXT.md code insights:

- A Zustand store slice (or extension of `ticketStore`) tracks `unseenChanges: Record<string, boolean>` — keyed by ticket key
- Hydrated from SQLite `has_unseen_changes` on app start via a new Tauri command (e.g. `get_unseen_change_keys`)
- Updated on `poll-complete` event: `PollCompletePayload.changed_keys` sets `unseenChanges[key] = true` for each key in the payload
- Cleared per ticket when the Changes tab is activated: invoke Tauri command `mark_changes_seen(issueKey)`, then set `unseenChanges[issueKey] = false` in the store
