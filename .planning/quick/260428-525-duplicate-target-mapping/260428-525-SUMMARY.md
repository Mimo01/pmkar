# Quick Task 260428-525: Fix Duplicate Target Field Mapping

## What Was Done

Enforced uniqueness on `target_field_id` at three independent layers so duplicate target mappings are impossible regardless of how the application is accessed.

## Changes

### Task 1 — DB: UNIQUE index on target_field_id
**Commit:** `09c2162`
**File:** `src-tauri/src/field_mapping_db.rs`

Added `ADD_UNIQUE_TARGET` migration constant that runs `CREATE UNIQUE INDEX IF NOT EXISTS idx_field_mapping_target_field_id ON field_mapping(target_field_id)`. Added `duplicate_target_field_id_is_rejected` test confirming the index rejects a second row with the same `target_field_id`.

### Task 2 — UI: filter used targets from MappingRow combobox
**Commit:** `20c3d0d`
**Files:** `src/features/field-mapping/MappingRow.tsx`, `src/features/field-mapping/FieldMappingSection.tsx`, `src/features/field-mapping/__tests__/MappingRow.test.tsx`

`FieldMappingSection.tsx`: added `usedTargetFieldIds` useMemo computing the set of already-selected target field IDs across all rows (excluding each row's own current selection). Passes `usedTargetFieldIds` as a prop to each `MappingRow`.

`MappingRow.tsx`: added `usedTargetFieldIds: Set<string>` prop, derives `availableTargetFields` by filtering out already-used targets, passes `availableTargetFields` to the target combobox instead of the full `targetFields` list. A row's own current target is excluded from the used set so an existing selection is never blanked out.

`MappingRow.test.tsx`: added `usedTargetFieldIds={new Set()}` to all render calls to satisfy the new required prop.

### Task 3 — Pipeline: duplicate guard in apply_mapping
**Commit:** `50bef2a`
**Files:** `src-tauri/src/field_transform/pipeline.rs`, `src-tauri/src/field_transform/mod.rs`, `src-tauri/src/commands.rs`

`mod.rs`: added `DuplicateTargetField(String)` variant to `TransformError`.

`pipeline.rs`: changed `apply_mapping` return type from `ResolvedFields` to `Result<ResolvedFields, TransformError>`. Before the insert loop, collects all `target_field_id` values into a `HashSet`, detects any duplicate, and returns `Err(TransformError::DuplicateTargetField(dup_id))` immediately. All existing tests updated to use `.expect("no duplicates")`. New test `duplicate_target_fields_returns_error` added.

`commands.rs`: updated the single `apply_mapping` call site to propagate the error via `.map_err(|e| AppError::Internal(e.to_string()))?`.

## Result

All three layers are now independently defensive:
- DB rejects duplicate `target_field_id` even from direct SQL
- UI never presents already-used targets as selectable options
- Pipeline returns a hard error rather than silently overwriting on any duplicate that bypasses the other layers
