Execute it in BOTH `open()` and `open_in_memory()` immediately after `conn.execute_batch(CREATE_FIELD_MAPPING)?;`:

```rust

```

Do NOT modify `CREATE_FIELD_MAPPING` itself — the table may already exist for users; a new unique index via `CREATE UNIQUE INDEX IF NOT EXISTS` is the safe migration path.

The `upsert_mapping_row` SQL already uses `ON CONFLICT(source_field_id)` — that clause is NOT affected by the new index. However, if a caller tries to insert a row whose `target_field_id` is already in use by a DIFFERENT `source_field_id`, SQLite will now return `SqliteFailure` with `UNIQUE constraint failed`. That error bubbles through `AppResult<()>` normally via the existing `From<rusqlite::Error>` impl as `AppError::Database`.

Add a test in the existing `#[cfg(test)]` block at the bottom of `field_mapping_db.rs`:

```rust
#[test]
fn duplicate_target_field_id_is_rejected() {
    let db = FieldMappingDb::open_in_memory().unwrap();
    // Wipe seed defaults so we control exactly what's in the table.
    db.conn.execute("DELETE FROM field_mapping", []).unwrap();
    let row_a = FieldMappingRow {
        source_field_id: "src_a".into(),
        target_field_id: "tgt_shared".into(),
        transformer_kind: "identity".into(),
        source_schema: serde_json::from_str("{\"type\":\"any\"}").unwrap(),
        target_schema: serde_json::from_str("{\"type\":\"any\"}").unwrap(),
    };
    let row_b = FieldMappingRow {
        source_field_id: "src_b".into(),
        target_field_id: "tgt_shared".into(),  // same target — must fail
        transformer_kind: "identity".into(),
        source_schema: serde_json::from_str("{\"type\":\"any\"}").unwrap(),
        target_schema: serde_json::from_str("{\"type\":\"any\"}").unwrap(),
    };
    db.upsert_mapping_row(&row_a).expect("first insert ok");
    let err = db.upsert_mapping_row(&row_b).expect_err("second insert must fail — duplicate target");
    let msg = err.to_string();
    assert!(
        msg.contains("UNIQUE") || msg.contains("constraint") || msg.contains("idx_fm_target_unique"),
        "error should mention unique constraint, got: {msg}"
    );
}
```

Note: `db.conn` is a private field — the test needs to live inside `field_mapping_db.rs` so it has access. The `DELETE FROM field_mapping` bypasses `seed_defaults_if_empty` so we have full control over fixture data.

   // Guard: reject mappings with duplicate target_field_ids before any insert.
   // Empty-sentinel rows (targetFieldId="") are excluded — they represent
   // "no target selected yet" and do not write to the fields map.
   let mut seen_targets: HashSet<&str> = HashSet::new();

       if row.target_field_id.is_empty() {
