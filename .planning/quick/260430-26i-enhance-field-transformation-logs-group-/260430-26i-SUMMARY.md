# Quick Task 260430-26i: Enhance field transformation logs (group by copy + Copy button + values) — Summary

Audit Log "Field Transformations" tab now groups rows by copy operation, exposes a per-group Copy button, and renders the actual redacted source/target values (with a graceful hash fallback for legacy rows). Backend persists `source_value_json` / `target_value_json` alongside the existing hash columns and the `audit_verbose` branch is removed.

## What changed

### Backend — schema, migration, command refactor

- `mapping_audit_log` table gains two nullable `TEXT` columns: `source_value_json`, `target_value_json`. Hash columns (`source_value_hash`, `target_value_hash`) retained verbatim for backward compatibility.
- `migrate_mapping_audit_log_columns` extended with two more idempotent guards (PRAGMA `table_info` + conditional `ALTER TABLE ADD COLUMN`). This is the established convention from quick-260430-0tj — to extend the table again, append guards to this same function (do **NOT** create a parallel migration function).
- `MappingAuditEntry` DTO adds `source_value_json: Option<String>` / `target_value_json: Option<String>` (camelCase via existing `#[serde(rename_all = "camelCase")]`).
- `insert_mapping_audit` appends two trailing `Option<&str>` parameters and binds them in the INSERT (10 → 12 columns / 10 → 12 binds). All 5 in-file test call sites pass `None, None`.
- `get_mapping_audit_log_page` SELECTs the two new columns at positions 11 and 12.
- `commands.rs::log_preview_transformations` no longer reads `triage_db.audit_verbose`; the `audit_verbose` branch is deleted and the command no longer takes a `triage_db` `State`. New behaviour: always compute `redact_string_in_value` once per side, then both `hash_field_value` AND `serde_json::to_string(...)` of the redacted value, then pass everything to `insert_mapping_audit`.
- `MAX_AUDIT_JSON_BYTES = 4096` constant + `cap_audit_json` helper truncate the persisted JSON on a UTF-8 char boundary (T-26i-04 mitigation).

### Frontend — grouped UI, copy button, value rendering

- `MappingAuditEntry` (TS) gains optional, nullable `sourceValueJson` / `targetValueJson` so legacy rows still type-check.
- `groupByCopyId(rows)` (exported) builds an insertion-ordered list of `FieldTransformationGroup` objects with pre-computed `total` / `failed` / `skipped` counts and `latestTimestamp = rows[0].timestamp` (since rows arrive newest-first from the Rust DESC query).
- `buildGroupCopyText(group)` (exported) produces a plain-text payload: header line, counts, then per-field `source: ...` / `target: ...` / optional `reason: ...` lines.
- The flat field-transformations table is replaced by a list of group cards. Each card has a single header `<button>` (with `aria-expanded`) plus a sibling Copy `<button>`. Header click toggles `expandedGroups: Set<string>`; Copy button calls `e.stopPropagation()` and reuses `copiedKey` (`group-${copyId}` key) + the 1500 ms revert timer.
- Row body shows source / target values via `valueOrHash`: prefers `sourceValueJson` / `targetValueJson` when present, otherwise renders the abbreviated hash with a "(hash only — legacy)" sub-label.
- Above the existing "Load more" button, a partial-group hint label is shown when `mappingHasMore`.

## Decisions Made

- **JSON cap = 4096 bytes (uniform):** preserves the prior `audit_verbose` cap so storage growth characteristics are unchanged, just always-on now. UTF-8-safe truncate via `cap_audit_json` prevents splitting multi-byte glyphs.
- **`triage_db` removed from `log_preview_transformations`:** the only reason it was held was the `audit_verbose` read; that branch is gone, the State is no longer needed. `get_audit_verbose` / `set_audit_verbose` on `TriageDb` left intact (out of scope).
- **groupByCopyId relies on input ordering:** rows arrive newest-first via Rust `ORDER BY id DESC`, so `Map` insertion order naturally puts the newest group first. No extra sort step.
- **Pre-existing test updated, not removed:** the `mapping_audit_tab_renders_rows` test still has value — it verifies the new UI loads field-transformation data into the DOM. Updating it to first expand groups keeps the regression coverage.
- **Slovak plural forms include `total_few`:** Slavic languages need three forms (1 / 2-4 / 5+); skipping `total_few` would make "2 polia" / "3 polia" render incorrectly via the `total_other` fallback.
