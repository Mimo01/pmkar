<objective>
Enhance the Audit Log "Field Transformations" tab with three connected improvements:

1. Group rows by `copy_id` into collapsible cards, ordered by the group's most-recent timestamp.
2. Add a per-group Copy button matching the API Audit tab's existing copy-to-clipboard pattern.
3. Persist the actual (redacted) source and target JSON values per row alongside the existing hashes, and surface them in both the UI and the copy-to-clipboard payload.

Purpose: when a copy fails or behaves unexpectedly, the user can now open the audit log, expand the relevant copy operation, see exactly what every field's source and resulting target value were, and copy the whole thing to a bug report in one click. Hashes were diagnostically useless on their own.

Output: schema migration + new DB columns, updated DTO + command, grouped UI with copy button, updated translations, and a Vitest covering grouping + copy text + value rendering. The existing flat-row data path is preserved for legacy rows whose JSON columns are NULL.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26i-01 | Information Disclosure | mapping_audit_log persisted JSON values | mitigate | Server-side `redact_string_in_value` runs BEFORE serialization (preserved from 0tj). All persisted JSON has emails/IPs/PII patterns + credential markers stripped. Tested by reusing existing `redact_string_in_value` unit tests. |
| T-26i-02 | Information Disclosure | Clipboard payload from Copy button | mitigate | Clipboard text is built from already-redacted DB rows — there is no separate raw-value path. The frontend never sees an unredacted value. |
| T-26i-03 | Tampering | source_value_json / target_value_json column writes | accept | These columns are written only by `log_preview_transformations`, which is invoked from the trusted frontend; values are bound via `params![]` (no SQL injection — pre-existing test `insert_mapping_audit_is_sql_injection_safe` extended to cover new columns by Task 1). |
| T-26i-04 | Denial of Service | Unbounded JSON value sizes blowing up SQLite | mitigate | `serde_json::to_string` of a redacted JSON value may be large. Truncate the persisted JSON string at 4096 bytes (the existing audit_verbose path already used this cap — apply the same cap to the new always-on JSON path) before passing into `insert_mapping_audit`. Document the cap in the migration comment. |
| T-26i-05 | Repudiation | Pre-existing rows have NULL JSON columns and look "missing" | accept | Documented in UI (legacy hash-only row label). No data loss — hash columns retained. |
