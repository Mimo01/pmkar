# Quick Task 261109-e83: Manually grouped tickets disappear when Jira no longer returns them - Context

**Gathered:** 2026-11-09
**Status:** Ready for planning

<domain>
## Task Boundary

For tickets the user manually put into a group: when Jira no longer returns them, they currently stay in the group view (dimmed "missing" block with Remove / Remove all confirm buttons, plus a tab-level "Remove all missing" popover). Change that so they disappear.

Current implementation touchpoints (scouted, not exhaustive):
- `src/features/groups/missingMembers.ts` — `computeMissingKeys` / `useMissingKeysByGroup` / `readMissingKeysNow`; missing only when hints eligible (complete, successful fetch — `useHintsEligible`, `useRemovalBlockedByFetch`)
- `src/features/groups/GroupViewPage.tsx` — partitions present vs missing, renders dimmed missing block with per-card + bulk remove
- `src/features/groups/RemoveMissingPopover.tsx` — tab-anchored "Remove all missing" confirm
- `src/features/groups/membershipActions.ts` — `removeMissingMember`, `removeAllMissingWithFeedback`
- `src/features/groups/useGroupMembers.ts` — returns `missingKeys`, `incomplete`
- Backend: `src-tauri/src/groups_db.rs`, `groups_commands.rs`

</domain>

<decisions>
## Implementation Decisions

### Disappear semantics
- AUTO-REMOVE MEMBERSHIP: when a member is missing (same eligibility rule as today — only after a complete, successful fetch; never on partial/truncated/errored/in-flight fetch), delete it from the group in the DB automatically. No confirmation. Not re-added if Jira returns it later. Group chip counts must reflect the removal.
- Safety is critical: the existing eligibility gate (hints eligible / not fetching) must be preserved so a transient or partial fetch never wipes group memberships. A recheck at removal time (like `readMissingKeysNow`) should guard races.

### Query/scope change (decided after research)
- NO GUARD: use the existing eligibility rule as-is (readHintsEligibleNow). User explicitly accepted that changing preset / custom JQL / source project / username / watched users will cause the next complete fetch to permanently remove members outside the new query. Do NOT add a first-fetch-after-signature-change skip or a "seen under this query" guard.

### Existing missing UI
- DELETE ENTIRELY: remove the dimmed missing section, per-card Remove + bulk Remove all confirms in GroupViewPage, the tab-level RemoveMissingPopover and its menu entry, related i18n strings (all locales), and obsolete tests. Replace with tests for auto-removal.

### Claude's Discretion
- Where auto-removal runs (frontend effect reacting to ticket store vs backend after poll) — pick whichever matches existing architecture and the eligibility gate most safely.
- Whether to show any feedback (e.g. silent vs toast) — default silent.

</decisions>
