- **Navigation choice:** relation rows call only `useTicketStore.getState().selectTicket(key)`. They do NOT call `markSeen` (`TicketListPage.handleSelectTicket` does). Reason: following a relation link must not silently change the triage state of a related ticket, which may not even be in the fetched list. Back still returns to the list (`handleDetailBack`). That is acceptable per research.
- **Snapshot/poll impact:** none. `poll_engine` uses search results only for keys, and diffs the detail fetch (`snapshot_db` WATCHED_FIELDS do not include subtasks/parent). Adding search fields does not create spurious "changed" badges.
- **Mock search:** `make_search_response_paged` (mock_server.rs:68) returns each fixture's full `fields` object and ignores `fields=`. So PROJ-1's existing `subtasks` already appear in the mock list, and the new `parent` on PROJ-7/8 will too. mock_server.rs needs no change. Do NOT add `parent` to the createmeta or field-list fixtures. It is not a mappable field. Copy mapping is field-mapping-driven, so `parent` on the source is not copied.
