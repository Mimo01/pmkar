# Quick Task 261021-m26: Ticket detail shows all sub-tasks or parent - Context

**Gathered:** 2026-10-21
**Status:** Ready for planning

<domain>
## Task Boundary

In ticket detail, show all of a ticket's sub-tasks, or its parent if it is a sub-task.

</domain>

<decisions>
## Implementation Decisions

### Placement and scope
- Move the relations block near the top of OverviewTab (above Description). Parent block for sub-tasks; Sub-tasks block for tickets that have them.
- Rows are clickable and open that ticket in the detail view (reuse existing navigation used for opening a ticket; no new patterns). Explicit, no hover-only icons.
- Applies to both TicketDetailPage and TicketDetailPanel (both render OverviewTab).

### Data source
- Use `fields.parent` / `fields.subtasks` from the existing issue response (`fields=*all`). No extra requests per related ticket.
- Add `parent` to JiraTicketDetail type and to OVERVIEW_BESPOKE_FIELDS so AllFieldsSection doesn't also render it.
- Mock server / fixtures: add a parent on a sub-task fixture and subtasks on a parent fixture so it can be seen in mock mode.

### Ticket list (added scope)
- Ticket list cards show relations at a glance, always visible, no expand toggle: a sub-task card lists its parent (key, summary, status); a parent card lists ALL its sub-tasks (key, summary, status) immediately.
- Add `subtasks,parent` to the search `fields=` in BOTH src-tauri/src/commands.rs (~751) and src-tauri/src/jira_client.rs (~57); extend JiraTicket type + cached ticket shape/serialization as needed (check Rust structs, store, cache, mock server search responses).
- Relation rows should be compact; clicking a row opens that ticket's detail. Keep card click behaviour intact (stopPropagation on relation rows). No hover-only icons, no DnD.

### Claude's Discretion
- Exact visual styling (match existing Linked Issues rows), i18n keys (EN + SK; SK term for issue is "tiket"), tests.

</decisions>
