# Quick Task 260429-v9y: Redesign Audit Log Table

## Goal

Make `AuditLogPage` easier to scan, search, and share. The log accumulates fast (hundreds of calls per session); right now a user can only scroll, click rows open one at a time, and visually parse status badges. Two concrete pain points:

1. **No way to find a specific call.** No search, no method filter, no status filter.
2. **No way to share a log entry.** When something goes wrong, the user has to manually re-type the URL, status, and response into a bug report or chat message.

This task adds a search/filter toolbar and a "Copy" action per log entry.

## Scope

**In scope (single file, single feature area):**

- `src/features/tickets/AuditLogPage.tsx` — UI redesign
- `src/i18n/locales/en.json` + `sk.json` — new strings
- `src/features/tickets/AuditLogPage.test.tsx` — update/extend tests

**Out of scope:**

- Backend changes (`get_audit_logs_page` already returns enough data)
- New columns requiring schema changes (e.g., duration — not in `AuditEntry`)
- Pagination redesign (existing "Load more" works)
- Real-time tail / auto-refresh

## Tasks

### Task 1 — Add filter toolbar (search + method + status)

**Files:**
- `src/features/tickets/AuditLogPage.tsx`
- `src/i18n/locales/en.json`
- `src/i18n/locales/sk.json`

**Action:**
- Insert a sticky toolbar between the header bar and the table containing:
  - Text search input (`type="search"`) — matches against `url` and `method` (case-insensitive substring)
  - Method filter: a `<select>` (or inline chips) with options `All / GET / POST / PUT / DELETE / Other`
  - Status filter: a `<select>` with options `All / 2xx / 3xx / 4xx / 5xx / Error`
  - Result count display: `{filtered}/{total}` — gives the user a sense of how aggressive their filter is
- Filter happens client-side over the already-loaded `entries` array (no new Tauri calls, no backend changes)
- Empty-after-filter state: show "No matching log entries" with a "Clear filters" button
- New i18n keys: `audit.search.placeholder`, `audit.filter.method`, `audit.filter.status`, `audit.filter.all`, `audit.filter.error`, `audit.filter.clear`, `audit.filter.empty`, `audit.count` (e.g., "{{shown}} of {{total}}")
- Ensure new controls are keyboard-focusable and labelled (aria-label or visible label) — matches Phase 9 a11y standard

**Verify:**
- `bun test src/features/tickets/AuditLogPage.test.tsx`
- Manual: filter by "POST", typing partial URL, status 4xx — expected entries appear

**Done when:**
- Toolbar renders above the table on all states (loading hides the toolbar; populated/empty-filter show it)
- Filter state combines (AND semantics): a row must match search AND method AND status
- Result count reflects the filter
- All new strings keyed in both `en.json` and `sk.json` with full Slovak diacritics (matches existing translation style)

### Task 2 — Add Copy-log button per entry

**Files:**
- `src/features/tickets/AuditLogPage.tsx`
- `src/i18n/locales/en.json`
- `src/i18n/locales/sk.json`

**Action:**
- In the expanded detail row, add a "Copy" button (top-right of the expanded panel) that copies a formatted, multi-section text representation of the entry to the clipboard. Format:
  ```
  [{timestamp}] {method} {url}
  Status: {statusCode or "Error"}

  Request Headers:
  {key}: {value}
  ...

  Response Body:
  {pretty-printed body, or "(empty)"}
  ```
- Clicking copies via `navigator.clipboard.writeText()` (modern Tauri webviews support this; no plugin needed)
- Visual feedback: button label briefly changes to "Copied ✓" for ~1500ms after a successful copy (`useState` timer pattern, cleanup on unmount)
- On clipboard failure (rare; e.g., feature unavailable), fall back to no-op + log via `console.warn` — do not throw
- Also add a small icon-only "Copy" button in the **summary row** (next to the status badge) that does the same thing without expanding — common case is "I just want to grab this URL/error fast"
- Stop click propagation on the icon-only button so it does not toggle row expansion
- New i18n keys: `audit.copy`, `audit.copied`

**Verify:**
- `bun test src/features/tickets/AuditLogPage.test.tsx`
- Manual: click expanded "Copy" → paste into note pad → see formatted block; click row-level icon copy → does NOT expand row

**Done when:**
- Both copy entry points produce identical formatted output
- Inline icon copy does not toggle row expansion
- Copied feedback shows and clears reliably (no leaked timer warnings in tests)
- All new strings keyed in `en.json` and `sk.json`

### Task 3 — Visual polish for readability

**Files:**
- `src/features/tickets/AuditLogPage.tsx`

**Action:**
- Restore method color contrast: current `methodColor` returns text colors that are barely visible on the `Badge variant="outline"` background. Tighten with the same green/blue/yellow/red tokens used in Phase 8 redesign but with proper bg/border tints (mirror the existing `renderStatusBadge` pattern).
- Make URL column slightly less aggressively truncated — remove the `max-w-0` trick that forces ellipsis at any width; instead allow the URL to flex while still preventing layout breakage with `truncate min-w-0`.
