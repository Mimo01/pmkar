  <action>
In main.rs, add a custom native application menu using Tauri 2.x menu API:

1. Add imports: `use tauri::menu::{Menu, MenuItem, Submenu, AboutMetadataBuilder, PredefinedMenuItem};`

2. Before `tauri::Builder::default()`, build a custom menu:
   - On macOS, create an app submenu with: a custom "About pmkar" MenuItem (id: "about"), separator, PredefinedMenuItem::services, separator, PredefinedMenuItem::hide, PredefinedMenuItem::hide_others, PredefinedMenuItem::show_all, separator, PredefinedMenuItem::quit
   - Add standard Edit submenu with: undo, redo, separator, cut, copy, paste, select_all
   - Add Window submenu with: minimize, PredefinedMenuItem::maximize (if available), separator, PredefinedMenuItem::close_window
   - Use `Menu::with_items` to assemble

3. Chain `.menu(menu)` on the Builder.

4. Add `.on_menu_event(|app, event| { if event.id() == "about" { let _ = app.emit("show-about", ()); } })` to the Builder to emit a frontend event when the About menu item is clicked.

Do NOT use `AboutMetadata` / `PredefinedMenuItem::about` — that opens the native About window. We want a custom MenuItem with id "about" that triggers our frontend modal instead.

Note: The Tauri 2.x menu API uses `Menu::with_items(app, &[...])` where `app` is the app handle. Build the menu inside the `.setup()` closure where `app` is available, then set it with `app.set_menu(menu)`. Alternatively, use the builder `.menu(|app| { ... })` closure pattern if supported. Check the Tauri 2 docs — the menu builder closure receives the app handle.

For cross-platform: The menu structure works on all platforms. On macOS, the first submenu becomes the app menu. On Windows/Linux, it becomes a standard menu bar.
