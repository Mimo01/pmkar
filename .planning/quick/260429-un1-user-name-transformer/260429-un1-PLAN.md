# Quick Task 260429-un1: Add user_name transformer for user→text mapping

## Goal

Add a `user_name` transformer that extracts the person's display name as plain text when
a source field of type `user` is mapped to a destination field of type `string`/`text`.

**Gap:** identity returns Null for user source types; the standard `user` transformer
resolves accountId (wrong shape for text fields); neither works for user→string.

## Tasks

### Task 1: TypeScript — transformer type + options
- `transformerOptions.ts`: add `'user_name'` to union, add `USER_NAME` option, add optional
  `sourceSchema` param, return `[USER_NAME]` when source=user AND target=string.
- `MappingRow.tsx`: pass `row.sourceSchema` to `getTransformerOptions` (both display and
  auto-select on target change).
- `SuggestionsPanel.tsx`: pass `s.sourceSchema` to `getTransformerOptions` on accept.

### Task 2: i18n
- `en.json`: add `settings.transformer.userName.{label,description}`
- `sk.json`: add Slovak translations

### Task 3: Rust pipeline dispatch
- `pipeline.rs`: check `transformer_kind == "user_name"` before generic `dispatch_user`.
- Add `dispatch_user_name()`: extracts `displayName` → `name` fallback → writes plain string.
  Array<user>: joins all names with ", ".

### Task 4: Tests (Rust)
Five new tests in `pipeline.rs::tests`:
- displayName extraction
- name fallback when no displayName
- array<user> → comma-joined string
- null user → field omitted (no gap)
- regression: standard `user` transformer still resolves accountId
