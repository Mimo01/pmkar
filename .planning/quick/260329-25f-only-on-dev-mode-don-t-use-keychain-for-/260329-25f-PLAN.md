<task type="auto">
  <name>Task 1: Add file-based credential backend for debug builds</name>
  <files>src-tauri/src/keychain.rs</files>
  <action>
Restructure keychain.rs to have two compile-time backends using `cfg(debug_assertions)`:

**Debug backend (new):**
- Store credentials as a JSON file at `~/.pmkar-dev-credentials.json` (home directory, NOT app data dir -- avoids needing Tauri app handle). Use `dirs::home_dir()` to get the path.
- Add `dirs` crate to Cargo.toml dependencies: `dirs = "6"` (lightweight, no extra features needed).
- The JSON structure: `{ "pmkar-jira-server:username": "secret_value", ... }` -- key is `"{service_name}:{username}"`, value is the secret string.
- `store_credential`: Read existing JSON (or empty object if file missing), insert/update the key, write back.
- `get_credential`: Read JSON, look up key, return error if not found (same error type as keychain miss).
- `delete_credential`: Read JSON, remove key, write back. Error if key not found (matching keyring behavior).
- Print `[dev] Using file-based credential store` to stderr on first access (use `std::sync::Once`).

**Release backend (existing, unchanged):**
- Keep the existing `keyring::Entry` based implementation exactly as-is.

**Structure the file like this:**
```rust
use crate::error::{AppError, AppResult};

const SERVICE_PREFIX: &str = "pmkar";

fn service_name(connection_type: &str) -> String {
    format!("{SERVICE_PREFIX}-{connection_type}")
}

// ---- Debug: file-based store ----
#[cfg(debug_assertions)]
mod file_store {
    // ... implementation
}

#[cfg(debug_assertions)]
pub fn store_credential(...) -> AppResult<()> { file_store::store(...) }
// etc.

// ---- Release: OS keychain ----
#[cfg(not(debug_assertions))]
pub fn store_credential(...) -> AppResult<()> { /* existing keyring code */ }
// etc.
```

Important: The `keyring` import should be behind `#[cfg(not(debug_assertions))]` so the keyring crate is still compiled (it's in Cargo.toml unconditionally) but not invoked in debug mode.
