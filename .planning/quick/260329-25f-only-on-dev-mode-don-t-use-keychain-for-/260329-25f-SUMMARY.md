# Quick Task 260329-25f: Dev-Mode File-Based Credential Store Summary

**One-liner:** Compile-time dual credential backend — JSON file (`~/.pmkar-dev-credentials.json`) in debug builds, OS keychain in release builds — eliminates keychain password prompts during development.

## What Was Built

`src-tauri/src/keychain.rs` now has two compile-time backends:

- **`#[cfg(debug_assertions)]`** — `file_store` module reads/writes `~/.pmkar-dev-credentials.json` as a `HashMap<String, String>` JSON file. Keys are `"{service}:{username}"` (e.g., `pmkar-jira-server:admin`). Access is serialised via a process-wide `OnceLock<Mutex<()>>` to prevent data races when tests run in parallel. Prints `[dev] Using file-based credential store` to stderr once via `std::sync::Once`.
- **`#[cfg(not(debug_assertions))]`** — Original `keyring::Entry` OS keychain implementation, completely unchanged.

The public API (`store_credential`, `get_credential`, `delete_credential`) is identical in both modes. No callers were modified.

The `dirs = "6"` crate was added to `Cargo.toml` for `dirs::home_dir()`.

Integration tests (`src-tauri/tests/keychain.rs`) were updated to:
- Remove the `keychain_available()` skip guard (not needed in debug — file backend is always available)
- Add `test_dev_credential_file_persistence` which reads the JSON file on disk to confirm the credential was physically persisted
- Keep release-mode skip guard under `#[cfg(not(debug_assertions))]`
