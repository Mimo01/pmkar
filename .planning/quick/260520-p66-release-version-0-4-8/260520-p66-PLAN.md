# Quick Task 260520-p66: Release version 0.4.8

## Objective

Bump version from 0.4.7 → 0.4.8 across all project files, commit the bump, create git tag v0.4.8, and publish a GitHub release with the changelog from commits since v0.4.7.

## Tasks

### Task 1: Bump version in all project files

**Files:**
- `package.json` — `"version": "0.4.7"` → `"0.4.8"`
- `src-tauri/Cargo.toml` — `version = "0.4.7"` → `"0.4.8"`
- `src-tauri/tauri.conf.json` — `"version": "0.4.7"` → `"0.4.8"`
- `CHANGELOG.md` — regenerated by git-cliff via bump script

**Action:** Run `node scripts/bump-version.mjs 0.4.8` from project root.

**Verify:** All three version files contain `0.4.8`:
```bash
grep -H '"version"' package.json src-tauri/tauri.conf.json && grep -H '^version' src-tauri/Cargo.toml
```

**Done:** Version string `0.4.8` present in package.json, src-tauri/Cargo.toml, src-tauri/tauri.conf.json. CHANGELOG.md updated with v0.4.8 section.

### Task 2: Commit, tag, and release

**Action:**
1. Commit version bump: `git commit -m "chore(release): bump version to 0.4.8"`
2. Create annotated tag: `git tag -a v0.4.8 -m "Release v0.4.8"`
3. Push tag: `git push origin v0.4.8`
4. Push commit to main: `git push origin main`
5. Create GitHub release via `gh release create v0.4.8 --generate-notes` (or use CHANGELOG.md section as body if `--notes-file` is preferred)

**Changelog (user-facing commits since v0.4.7):**
- feat: add static value mapping for any field type — pick a fixed target value when no source field maps (Phase 27)
- feat: add static priority mapping + static issuetype mapping (issuetype wins over per-copy chooser)
- fix: seed IssueTypeChooser from static issuetype mapping in startPreview
- fix: eagerly fetch priorities so static priority mapping works in settings

**Verify:**
```bash
git tag -l v0.4.8 && gh release view v0.4.8 --json url -q .url
```

**Done:** Commit pushed to origin/main, tag v0.4.8 pushed to origin, GitHub release published and visible via `gh release view v0.4.8`.
